# AGENTS.md

Mivara (幻屏): C++17 LAN screen-mirroring / wireless second monitor.
Cross-platform (Windows / Linux X11 / macOS). Single package, no monorepo — everything is in `src/` and one `makefile`.

**Renamed 2026-10-13: TwinView → Mivara (幻屏).** GitHub links to the old name redirect (301). The local checkout directory on this machine is still `D:\projects\TwinView\` — path references to it are intentional.

Full user docs: `README.md` (Chinese) + `README_EN.md` (English twin). This file only covers what an agent would otherwise get wrong.

**Rule: keep `README.md` and `README_EN.md` in sync** — any edit to one must be mirrored in the other. Terminology: say 「扩展 / Extend」 for the real extended desktop (virtual-display mode); no "真·扩展屏 / True extend" qualifiers.

## Build

```bash
make                  # all three: bin/sender, bin/receiver, bin/app
make sender           # one binary (also: receiver, app)
make debug            # -g -O0 -DDEBUG — note: runs clean first, full rebuild
make check            # env/source self-check (the only "verification" step)
make install-deps     # apt/dnf/pacman/brew + MSYS2
make OPT_FLAGS="-O3 -march=x86-64 -flto"   # portable build for releases/installer
```

- Default release flags: `-O3 -march=native -flto` — host-specific, do not redistribute. **Release/installer builds must override OPT_FLAGS** with `-march=x86-64` (see above).
- Binaries + runtime DLL closure output to `bin/`; objects go to `build/`.
- `gpu_accelerate.c` is C (gcc); all other sources are C++17 (g++). Keep it valid C.
- Makefile header deps are listed manually (see `Header Change Tracking Maps` block). Adding a new `.h` without adding it there causes stale builds.
- SDL flags are added only to the `app`/`receiver` objects and to `theme.o` (`OBJ_APP OBJ_RECEIVER OBJ_THEME` — theme.h pulls in `<SDL2/SDL.h>`, and theme.o is linked into `app` only). Never add them to `sender` — pkg-config sdl2 cflags contain `-Dmain=SDL_main`, which breaks sender's link since it has no SDL2main.
- No CMake, no test suite, no lint/format/typecheck config, no CI workflows. Do not invent test commands.

### Toolchain on this machine

- `make`/`g++` are not in the Windows PATH — run builds via `C:\msys64\usr\bin\bash.exe -lc "export PATH=/mingw64/bin:/usr/bin:$PATH OS=Windows_NT && cd /d/projects/TwinView && make ..."`. The makefile's whole Windows branch is keyed on `$(OS)`; in sandboxed shells where `OS` is unset, links silently lose all system libs (`-lws2_32`, `-lgdi32`, `-lsetupapi`, …) and there is no `.exe` suffix.
- Git is `D:\Program Files\Git\cmd\git.exe` (not in PATH). GitHub 443 direct often times out while curl works; push with `-c http.proxy=http://127.0.0.1:7890` (FlClash).
- Windows PowerShell here is 5.1: **no `&&`** in commands. Avoid `$_` in double-quoted one-liners (bash eats it) — write a `.ps1` file instead.
- Interactive UAC elevation (`Start-Process -Verb RunAs`) is silently blocked in this environment — can't automate elevated tests; ask the user to double-click the exe.

## Installer (Inno Setup)

- `installer/Mivara.iss` packages `bin/` + `scripts/` + `vdd/` drivers (excludes the >100 MB vendor GUI) into `dist/Mivara-Setup-<ver>.exe`.
- GitHub Release assets must include both `Mivara-Setup-<ver>.exe` and a **fixed-name copy `Mivara-Setup.exe`** — `https://github.com/wzy-777/Mivara/releases/latest/download/Mivara-Setup.exe` is the permanent latest-installer link (the README download badges point at it) **and the exact URL the in-app updater downloads**, so a release missing the fixed-name copy silently downgrades every client's 下载更新 to the browser path. The CI artifact already carries all three files (both names + `SHA256SUMS.txt`); only a *local* build needs the manual copy: `cp dist/Mivara-Setup-<ver>.exe dist/Mivara-Setup.exe`.
- Build: `"D:\Program Files\Inno Setup 6\ISCC.exe" installer\Mivara.iss` (ISCC is at that custom path on this machine, not Program Files).
- Wizard language: this Inno install lacks `ChineseSimplified.isl`, so the installer UI is English; a comment in the .iss explains how to enable Chinese.
- **Version single source `src/version.h`** (`#define MIVARA_VERSION "X.Y.Z"`, no `v`). The .iss pulls it in with ISPP (`#include "..\src\version.h"` + `#define AppVersion MIVARA_VERSION`), `sender.cpp`/`receiver.cpp` banners and `app.cpp` compose it at compile time. Release step: bump `src/version.h` — **that file must stay comment-free** (an inline `//` after a directive aborts ISCC 6.6.1; verified) — then hand-edit the version badge in both READMEs and the `winget/` manifests, which stay manual. Use `vX.Y.Z`-style release tags: the updater parses `releases/latest`'s 302 `Location` and a malformed tag degrades to 「版本号格式异常」.
- **Every release must attach `SHA256SUMS.txt`** in `sha256sum` format with a line for `Mivara-Setup.exe` (the CI job generates it in `dist/`; see below). The in-app installer is fail-closed: without that line it refuses to install and falls back to opening the release page. If SignPath signing goes live, regenerate the file from the **signed** installer.
- The post-install "launch" checkbox must keep the `runascurrentuser` flag: `postinstall` entries default to `runasoriginaluser` (unelevated) and `app.exe` is `requireAdministrator`, so without it CreateProcess fails with ERROR_ELEVATION_REQUIRED. `[UninstallRun]` removes the `Mivara` Task Scheduler job registered by app auto-start (task name must match `applyAutoStart` in app.cpp).
- Release notes must include the assets' SHA-256 (the versioned file and the fixed-name copy are the same binary — one hash covers both; quote it against the versioned name) — same hash as `SHA256SUMS.txt`. The SmartScreen FAQ lives under Troubleshooting in both READMEs (anchors `#windows-smartscreen-提示说明` / `#windows-smartscreen-notice`); release notes link to it.
- `winget/` holds the winget-pkgs submission manifests — copy into `manifests/w/wzy-777/Mivara/<version>/` of microsoft/winget-pkgs and open a PR each release. winget installation bypasses the SmartScreen prompts (the default community source rewrites MOTW to the trusted zone) — the only no-code-signing channel that does.
- `.github/workflows/release-installer.yml` builds the portable installer in GitHub Actions (MSYS2 MinGW64 + Inno Setup; the `OS=Windows_NT` export is required there too, and `OPT_FLAGS` is overridden for portability). It also writes `dist/SHA256SUMS.txt` (uploaded with the installer artifact) — attach it to the release. It exists both for reproducible releases and because SignPath's free OSS signing requires the signed artifact to come from a trusted build system — locally built installers cannot be submitted. SignPath steps are gated on the repo variable `SIGNPATH_ENABLED`; re-verify action input names at docs.signpath.io when enabling after approval. `CODE_SIGNING_POLICY.md` (root) is a SignPath application precondition — keep it accurate once signing is live.

## Windows specifics (easy to get wrong)

- `sender` links as a **console** subsystem app (logs + interactive prompts + Ctrl+C). `receiver` and `app` link with `-mwindows` (GUI, stdout discarded).
- SDL2_ttf needs a CJK font at runtime; `app.cpp` walks an ~11-path candidate list (`msyh.ttc`/`simhei.ttf`/NotoSansCJK/wqy/…) and exits with an error if none is found. Caveat: the list also contains non-CJK `DejaVuSans.ttf`, so on a machine with no CJK font the probe can "succeed" via DejaVu and render tofu instead of erroring.
- The runtime DLL closure must sit in `bin/` next to the exes (already there). After adding a library, verify with `ldd bin/<exe>.exe` and copy missing DLLs into `bin/`.
- Extend mode needs the MttVDD indirect-display driver installed once (`vdd/install_vdd.ps1`). The virtual display lifecycle lives in `src/vdd.cpp`/`vdd.h` (`vddStartup`/`vddShutdown`/`vddForceDetach`, CCD API + SetupAPI device enable/disable) and is linked into both `sender` and `app`. **Never break the Ctrl+C graceful path** — a hard exit leaves the virtual display attached to the user's desktop. Covered exit paths: normal end, send failure, Ctrl+C, console-window close (detaches inside the `CTRL_CLOSE_EVENT` handler), `atexit`. The GUI stops the sender by sending Ctrl+C (`GenerateConsoleCtrlEvent`), hard-kills only after an 8 s timeout, and calls `vddForceDetach()` as a safety net after a hard kill.
- A CCD detach alone leaves the monitor visible in Settings > Display — teardown MUST also disable the PnP device (hardware ID `Root\MttVDD`, instance `ROOT\DISPLAY\000x`; match on hardware IDs, never touch other vendors' virtual display adapters). Enabling/disabling requires elevation: `sender` and `app` embed a `requireAdministrator` manifest via `res/admin.rc` + `res/admin.manifest` (windres, see makefile `RES_ADMIN`). `receiver` is not elevated. Disable failure degrades gracefully (warn + CCD-only). A disabled device has no CCD path — `vddStartup` must enable the device **before** the `vddInstalled()` gate.
- `scripts/*.bat` are convenience wrappers that launch `bin/` exes; `启动投屏发送.bat` takes the receiver IP as an argument.

## Architecture (actual wiring)

| File | Role |
|------|------|
| `src/sender.cpp` | capture (GDI/X11/CoreGraphics), handshake, streaming, runtime reconfigure (SETP). |
| `src/vdd.cpp/.h` | Windows virtual display (MttVDD) lifecycle: enable/disable PnP device (SetupAPI) + attach/detach/position via CCD API. Linked into sender + app. |
| `src/receiver.cpp` | SSDP broadcast, SDL2 fullscreen render, hosts the two sidecar services |
| `src/discover.cpp/.h` | SSDP discovery engine (UDP 1900); parses SSDP `NAME:` into `DiscoveredDevice.name` |
| `src/gpu_accelerate.c/.h` | remote CPU offload protocol (RLE compress / color convert) served on 8082 — only used by the RLE codec path |
| `src/ports.cpp/.h` | remote port inspector on 8083 (LIST/GET/KILL) |
| `src/proto.h` | protocol v2 shared by sender/receiver: HsRequestV2/HsResponseV2, CodecId, control packets |
| `src/codec.h/.cpp` | FFmpeg Encoder/Decoder (H.264/H.265/AV1). Linked into sender + receiver only (app is FFmpeg-free) |
| `src/config.h/.cpp` | GUI settings (%LOCALAPPDATA%\\Mivara\\config.ini), key=value (incl. `auto_start` → Task Scheduler `Mivara` job, `auto_receive`, `theme` = light\|dark\|system) |
| `src/history.h/.cpp` | connection history (history.ini, cap 20, newest first) |
| `src/theme.h/.cpp` | GUI palette: light/dark token sets + follow-system resolution (`themeTick`, Windows registry `AppsUseLightTheme` polled every 2 s; macOS/Linux sampled once per process — the popen is never repeated, so at most one UI-thread sample is ever taken, which lands on the first 跟随系统 click if the app was launched in light/dark). app.cpp colours come from `theme()`; the only exceptions are the two mode-independent constants in theme.h (`DANGER_SOLID`, `SWITCH_ON`), plain white (toggle knob, the danger-button label, the chip/banner hover washes) and plain black (the danger button's hover wash). |
| `src/app.cpp` | SDL2 + SDL2_ttf GUI launcher: header (wordmark + 更新 button, present only while a release is waiting + icon appearance switcher: sun 亮色 / moon 暗色 / monitor 跟随系统) over a left nav (主页/设置) + session flows and connection history inside 主页 (history rows under the 接收/发送 cards; no separate history tab); SSDP search, device list (投屏/扩展), manual IP, settings; spawns sender/receiver as child processes with hidden console + stdout pipe (STAT| status panel + log window) and a **stdin pipe carrying `SETP|` reconfigure lines**. Layout lives in the `shared layout` macro block — `buildButtons()` (hit rects) and `renderScreen()` (painted rects) both read it, so a control can never be drawn in one place and clicked in another; keep it that way. Appearance is the only setting with two controls (header + 外观 card), so its ids are matched against the `kThemeIds` table, never derived by subtracting a base: a `(id >= BTN_SET_THEME_BASE) ? …` range test is true for the header ids too (8020 ≥ 7070) and once indexed `modes[950]` out of bounds, which silently made every header click fall back to 亮色. **Display scale (`g_uiScale`)** — the layout is a fixed 880×700 logical grid and SDL makes the process per-monitor DPI aware, so without this the UI is drawn 1:1 and lands 25 % small on a 125 % display with one-pixel CJK strokes (the "jagged text" complaint). main() resolves it once (quarter steps, capped to the usable screen), the window is created at `uiPx(WIN_*)`, `SDL_RenderSetScale` scales every shape, fonts open at `uiPx(size)` and text blits itself in device pixels (`drawTextPx`), pointer coords are divided by `uiCoord()` at the event boundary (`floor`, not `lround` — the renderer paints a scaled rect as `[floor(x*s), ceil((x+w)*s))`, so rounding to nearest shifts every hit rect a pixel left at 2× and makes an edge-sharing chip select its neighbour), and `fitText()` compares in device pixels. Any new layout constant stays logical; any new direct pixel measurement must go through `uiPx`/`uiCoord` or it will be wrong at ≠1×. **Shape antialiasing** — SDL's shape primitives have no AA, and `SDL_RenderSetScale` scales a primitive's *coordinates* but not its *thickness*, so at 1.25× the shipped build drew the toggle pills, the warning triangle and every 1px hairline as striped scanline bands on the D3D9 backend. `fillCircle` / `fillRoundRect` / `drawRing` / `drawGlyph` / `glyphWarning` therefore blit a cached coverage mask (`g_masks`, per-renderer, dropped in `closeLogWindow` and at exit) instead of calling the primitives. Invariants: masks are baked by running the **shipped rasteriser** (`fillCircleRaw` / `fillRoundRectRaw`, kept verbatim as `*Raw`) at `MASK_SS`× by multiplying the *geometry*, never by setting the render scale — the software backend scales a `RenderDrawLine`'s coordinates but not its thickness, so a scaled scanline combs the shape; a glyph body's stroke width is hardcoded in canvas pixels, so **glyph masks bake at logical resolution** and are upscaled with `SDL_ScaleModeLinear` (baking them supersampled shrinks every stem to a hairline); AA passes run inside a `ScaleScope` (save → force 1.0 → restore) because `SDL_RenderCopyEx` honours the ambient scale; `fillRoundRect`'s corner-mask blits must abut the edge bands exactly, never overlap; every mask's transparent pixels must carry **white** RGB — `MaskCanvas` clears to `(0,0,0,0)`, so a mask must be built through `coverageFrom` (which forces `0x00FFFFFF`) rather than uploaded raw, because the linear upscale interpolates RGB as well as alpha and a black transparent pixel multiplies the glyph by its own coverage a second time, greying every antialiased edge; and each shape must be baked about the **centre of the output pixel's supersample block** (`R * MASK_SS + MASK_SS / 2`), not the block's first canvas pixel, or the whole shape lands a fraction of a device pixel up-left (the disc's coverage centroid sits 0.13 device px from the pre-AA rasteriser's placement after this correction, 0.38 before). Note the placement convention the masks must preserve: a disc at logical `(cx, cy)` is centred on **pixel index** `uiPx(cx)`, i.e. continuous `uiPx(cx) + 0.5` — matching the pre-AA `fillCircleRaw` — which is a constant 0.5 px off jagprobe's analytic "ideal centre", so that probe's absolute disc RMS is biased and must not be read as a placement error. Any new shape drawn with a raw SDL primitive will be jagged at ≠1× — route it through a mask. |
| `src/update.h/.cpp` | app-only update check + in-app updater (settings 更新 row, home banner, header button, nav dot). Check = one HTTPS GET of `releases/latest`, version from the 302 `Location` — **never `api.github.com`** (60/h per unauthenticated IP). Windows download lands in `%ProgramData%\Mivara\Updates`, which is taken over with owner=Administrators + a **protected** DACL (SYSTEM/Admins full, Users read/execute, inheritance dropped) and then read back to confirm; the installer is verified against the release's `SHA256SUMS.txt` (fail-closed) and re-hashed right before launch. POSIX builds only check + open the release page. Links `-lwinhttp -lbcrypt -ladvapi32`. **One-click path:** the header button (`BTN_HDR_UPDATE`, ghost hit area painted by `drawHeader`) sets `g_upd_auto_install`, and the `updateTake()` completion hook runs `startInstall()` itself once the package verifies — except while a sender/receiver child is live, where quitting would kill the session; then the button turns green and waits for a second click. Only the header button arms that flag: 下载更新 in the 更新 card still stops at 立即安装. |
| `src/version.h` | single version source (`MIVARA_VERSION`, bare `X.Y.Z`) consumed by C++ **and by the Inno preprocessor** — keep it comment-free. |

- `ports.cpp` has a hidden `main()` behind `-DPORTS_MAIN` — can be compiled standalone as a port-inspection CLI. The makefile never sets this flag; don't be confused by two `main` functions in the tree.
- `sender` CLI: `sender [ip] [port] [--mode mirror|extend] [--codec auto|h264|h265|av1|raw|rle] [--hw 0|1] [--bitrate <kbps>] [--quality 0-51] [--fps <n>] [--scale <pct>] [--chroma 420|444]`. `--mode` skips all interactive prompts — the GUI depends on it. Keep it working non-interactively. After streaming starts, a reader thread consumes stdin lines (`SETP|k=v|…` / `PING`) — stdin may be a GUI pipe, so never treat it as an interactive prompt channel once the loop begins.
- File-size orientation: `app.cpp` (~3000 lines) is by far the largest source, then `ports.cpp` (~1600) and `sender.cpp` (~1585).
- `receiver`'s 8082/8083 sidecar services are unconditional `for(;;) accept` loops that never check `g_running` — once `g_running` clears (window quit / SIGINT), `main` blocks joining them and never reaches final cleanup (stats flush / shutdown summary skipped; standalone runs linger). The GUI's graceful stop does not apply to it in the default hidden-console launch: `receiver` is a GUI-subsystem exe with no console, so `stopChild`'s `AttachConsole` fails and it is TerminateProcess'd immediately — the 8 s Ctrl+C-then-kill path is for the console-subsystem `sender` (POSIX GUI: SIGINT → 3 s → SIGKILL). Any shutdown refactor must handle these loops.
- The 8083 port inspector has **no authentication** — any LAN peer that can reach the port can LIST/GET/KILL receiver-side processes. Keep it LAN-only.
- The updater is self-contained and must stay that way: it never touches the protocol, the VDD path, the children or the config, and the worker thread never calls SDL/`logPush`/`configSave` (the UI polls `updateTake()` once per frame). Invariants to preserve: only `github.com/wzy-777/Mivara` is contacted (User-Agent only, nothing uploaded); redirects are followed only for downloads and the **final URL must land on `github.com`/`*.githubusercontent.com` over HTTPS or no body byte is read**; the tag is validated to a fixed charset before it builds a URL or file name; in-app install is fail-closed on a missing `SHA256SUMS.txt` entry. `src/update.cpp` carries a hidden CLI behind `-DUPDATE_TEST_MAIN` (cf. `-DPORTS_MAIN`): `unit` / `check` / `download <tag>` / `hash <file>` — the makefile never sets the flag.

## Protocol constants (defined in `src/proto.h`)

- Handshake over TCP 8081 (**protocol v2**, all u32 network byte order, magic `0x54564853` 'TVHS'):
  - Request (sender→receiver) `HsRequestV2` **48 bytes**: magic, version=2, width, height, fps, mode, codec, codec_flags, bitrate_kbps, quality, gop_frames, reserved.
  - Response (receiver→sender) `HsResponseV2` **36 bytes**: magic, version, recv_width, recv_height, status, codec, codec_flags, reserved[2].
  - `mode`: 0 = mirror, 1 = extend. `codec`: 0=raw 1=rle 2=h264 3=h265 4=av1. `status`: 0=ok 1=version 2=codec 3=dims 4=decoder 5=legacy.
  - Receiver peeks 4 bytes first: non-TVHS magic ⇒ legacy peer, explicit error (no black screen). Old 16-byte handshake is rejected.
- Stream packets: `[u32 pkt_size][payload]`; control = `u32 0xFFFFFFFF` + `u32 ctrl_type` + body. `CTRL_RESIZE=1` body = HsRequestV2; `CTRL_FORCE_IDR=2` / `CTRL_EOS=3` body empty; `CTRL_RECONFIG=4` body = HsRequestV2 (runtime param change — receiver re-opens the decoder and sets `skip_until_key`, see the shared resize/reconfig handler in receiver.cpp).
- Coded payload = one access unit per packet (annex-B / OBU). Raw/RLE unchanged. 8082 remote RLE is connected **only** while `codec=rle` (connect/disconnect follows runtime codec switches).
- STAT| machine-readable status lines on stdout (parsed by the GUI): `STAT|k=v|k=v|...` with keys t/frames/fps/kbps/codec/hw/mode/src/dst/quality or `event=start|stop|error|applied|pong` + `msg=`. The parser replaces its state per line, but not every line is a full snapshot: only periodic lines and `event=applied` carry the full key set — `start`/`stop`/`error`/`pong` carry subsets (sender `error` = `msg=` only; the receiver emits its own `start`/`stop`/`error`/`resize`/`reconfig` variants). The GUI special-cases event lines; check `parseStatLine` in app.cpp before changing emitter key sets.
- GUI→sender stdin line protocol (runtime reconfigure): `SETP|codec=…|hw=…|bitrate=…|quality=…|fps=…|scale=…|chroma=…` (any subset; keys map to the CLI flags; numeric values must be whole decimal numbers — parse with a strict whole-token check, never `atoi`; all-or-nothing validation, reply `STAT|event=applied|…` or `STAT|event=error|msg=bad_value_*`). `PING` → `STAT|event=pong`.
- Ports: 1900/udp SSDP, 8081/tcp video, 8082/tcp compute offload (`GPU_ACCEL_PORT`), 8083/tcp port inspector (`PORTS_SERVICE_PORT`).
- SSDP discovery: sender probes **per local NIC** over 3 rounds (~100 ms apart), each sending multicast + 255.255.255.255 + a directed per-NIC subnet broadcast (enterprise nets often drop multicast). Replies are keyed on the **datagram source address**, with the LOCATION IP probed only as a fallback (multi-homed receivers may advertise the wrong NIC). Receiver's LOCATION uses `getLocalIPForPeer(requester)` (same-subnet NIC). Receiver advertises `NAME: <hostname>`.
- Windows `SO_RCVTIMEO`/`SO_SNDTIMEO` take DWORD milliseconds, not `struct timeval` (POSIX). Passing a timeval silently gives ~5 ms timeouts.
- Sender and receiver must be the **same binary version** (protocol v2). Mismatched builds fail the handshake with an explicit error — never silently black-screen.
