# AGENTS.md

Mivara (幻屏): C++17 LAN screen-mirroring / wireless second monitor.
Cross-platform (Windows / Linux X11 / macOS). Single package, no monorepo — everything is in `src/` and one `makefile`.

User docs: `README.md` / `README_EN.md` are the short landing pages; long-form documentation lives in `docs/zh/` and `docs/en/` (index: `docs/README.md`, screenshots in `docs/assets/`). This file only covers what an agent would otherwise get wrong.

**Rule: keep `README.md` and `README_EN.md` in sync** — any edit to one must be mirrored in the other. Every `docs/zh/<page>.md` has a `docs/en/<page>.md` twin with the same heading order, tables and code blocks; edit both. The README badge anchors (`#环境要求` / `#requirements`) and the SmartScreen anchors depend on those exact headings. Terminology: say 「扩展 / Extend」 for the real extended desktop (virtual-display mode); no "真·扩展屏 / True extend" qualifiers.

## Build

```bash
make                  # all three: bin/sender, bin/receiver, bin/app
make sender           # one binary (also: receiver, app)
make debug            # -g -O0 -DDEBUG — note: runs clean first, full rebuild
make run              # run the GUI from bin/
make run-sender       # run bin/sender directly
make run-receiver     # run bin/receiver directly
make check            # env/source self-check (the only "verification" step)
make install-deps     # apt/dnf/pacman/brew + MSYS2
# On Windows, make also runs copy-dlls, which copies the mingw64 runtime DLL closure into bin/.
make OPT_FLAGS="-O3 -march=x86-64 -flto"   # portable build for releases/installer
```

- Default release flags: `-O3 -march=native -flto` — host-specific, do not redistribute. **Release/installer builds must override OPT_FLAGS** with `-march=x86-64` (see above).
- Binaries + runtime DLL closure output to `bin/`; objects go to `build/`.
- `gpu_accelerate.c` is C (gcc); all other sources are C++17 (g++). Keep it valid C.
- Makefile header deps are listed manually (see `Header Change Tracking Maps` block). Adding a new `.h` without adding it there causes stale builds. `make check` keeps a second hand-written source list (the `check:` target) — add new or renamed sources there too, or it reports MISSING.
- SDL flags are added only to the `app`/`receiver` objects and to `theme.o` (`OBJ_APP OBJ_RECEIVER OBJ_THEME` — theme.h pulls in `<SDL2/SDL.h>`, and theme.o is linked into `app` only). Never add them to `sender` — pkg-config sdl2 cflags contain `-Dmain=SDL_main`, which breaks sender's link since it has no SDL2main.
- No CMake, no test suite, no lint/format/typecheck config. The only CI is `.github/workflows/release-installer.yml` (portable installer build); do not invent test commands.

### Toolchain

- `make`/`g++` are not in the Windows PATH — run builds through MSYS2: `C:/msys64/usr/bin/bash.exe -lc "export PATH=/mingw64/bin:/usr/bin:$PATH OS=Windows_NT && cd /d/<repo> && make ..."`. The makefile's whole Windows branch is keyed on `$(OS)`; in sandboxed shells where `OS` is unset, links silently lose all system libs (`-lws2_32`, `-lgdi32`, `-lsetupapi`, …) and there is no `.exe` suffix.
- Git and `gh` are expected on PATH (or set `GH=`). If direct GitHub access is blocked, set `PROXY=<http proxy>`; `release.sh` only falls back to it after a direct attempt fails.
- Machine-specific toolchain notes (exact install paths, local shell quirks) live in `.claude/local-notes.md`, which is gitignored; read it if present. Keep this file portable.

## Installer (Inno Setup)

- `installer/Mivara.iss` packages `bin/` + `scripts/` + the `vdd/` driver (x86/AMD64 and ARM64; excludes the >100 MB vendor GUI) + the offline docs (`README.md`, `README_EN.md`, `LICENSE`, `CODE_SIGNING_POLICY.md`, `SECURITY.md`, `THIRD-PARTY-NOTICES.md`, `vdd/LICENSE`, `docs/`) into `dist/Mivara-Setup-<ver>.exe`.
- Third-party licensing: the bundled VDD is MIT (notice in `vdd/LICENSE`); `THIRD-PARTY-NOTICES.md` covers SDL2/SDL2_ttf, FFmpeg, devcon and the runtime DLL closure. **The CI FFmpeg package (`mingw-w64-x86_64-ffmpeg`) is GPL-3.0-or-later (`--enable-gpl --enable-version3`), so the combined release binary must be distributed under GPL-3.0-or-later terms** — an LGPL FFmpeg build is the alternative if an MIT-only binary is required. The GPL text lives in `LICENSES/GPL-3.0-or-later` (packaged with the installer; the `LICENSES` directory has no `.txt` suffix on purpose because `.gitignore` drops `*.txt`), and both READMEs plus the winget `License` field declare GPL-3.0-or-later for the binaries while the source repo stays MIT. Keep the notices and license text in the installer. The unused virtual audio driver was removed — do not re-add it.
- GitHub Release assets must include both `Mivara-Setup-<ver>.exe` and a **fixed-name copy `Mivara-Setup.exe`** — `https://github.com/wzy-777/Mivara/releases/latest/download/Mivara-Setup.exe` is the permanent latest-installer link (the README download badges point at it) **and the exact URL the in-app updater downloads**, so a release missing the fixed-name copy silently downgrades every client's 下载更新 to the browser path. The CI artifact already carries all three files (both names + `SHA256SUMS.txt`); only a *local* build needs the manual copy: `cp dist/Mivara-Setup-<ver>.exe dist/Mivara-Setup.exe`.
- Build: `ISCC.exe installer\Mivara.iss` (set `ISCC=` if ISCC is not on PATH).
- Wizard language: this Inno install lacks `ChineseSimplified.isl`, so the installer UI is English; a comment in the .iss explains how to enable Chinese.
- **Version single source `src/version.h`** (`#define MIVARA_VERSION "X.Y.Z"`, no `v`). The .iss pulls it in with ISPP (`#include "..\src\version.h"` + `#define AppVersion MIVARA_VERSION`), `sender.cpp`/`receiver.cpp` banners and `app.cpp` compose it at compile time. Release step: bump `src/version.h` — **that file must stay comment-free** (an inline `//` after a directive aborts ISCC 6.6.1; verified) — then hand-edit the version badge in both READMEs and the `winget/` manifests — or let `release.sh` (below) do all of it. Use `vX.Y.Z`-style release tags: the updater parses `releases/latest`'s 302 `Location` and a malformed tag degrades to 「版本号格式异常」.
- **Every release must attach `SHA256SUMS.txt`** in `sha256sum` format with a line for `Mivara-Setup.exe` (the CI job generates it in `dist/`; see below). The in-app installer is fail-closed: without that line it refuses to install and falls back to opening the release page. If SignPath signing goes live, regenerate the file from the **signed** installer.
- The post-install "launch" checkbox must keep the `runascurrentuser` flag: `postinstall` entries default to `runasoriginaluser` (unelevated) and `app.exe` is `requireAdministrator`, so without it CreateProcess fails with ERROR_ELEVATION_REQUIRED. `[UninstallRun]` removes the `Mivara` Task Scheduler job registered by app auto-start (task name must match `applyAutoStart` in app.cpp).
- Release notes must include the assets' SHA-256 (the versioned file and the fixed-name copy are the same binary — one hash covers both; quote it against the versioned name) — same hash as `SHA256SUMS.txt`. The full SmartScreen FAQ lives in `docs/zh/troubleshooting.md` / `docs/en/troubleshooting.md` (headings `## Windows SmartScreen 提示说明` / `## Windows SmartScreen Notice`); both READMEs keep a short note with the same headings so the anchors `#windows-smartscreen-提示说明` / `#windows-smartscreen-notice` still resolve. Release notes link to those anchors.
- `winget/` holds the winget-pkgs submission manifests — `winget/submit.sh <ver>` copies them into `manifests/w/wzy-777/Mivara/<version>/` of microsoft/winget-pkgs and creates/updates the PR (release.sh calls it automatically; `--no-winget-pr` opts out). It never clones the ~1M-file repository: blobs/trees/commits go through the Git Data API on the `wzy-777/winget-pkgs` fork. Rules it encodes: **one PR per package** (an open PR authored by the same gh user is updated on its own head branch rather than duplicated), a **new-package PR carries exactly one version** (unpublished version dirs are deleted from the PR branch; versions already upstream are never touched), and it is idempotent (identical blobs + no stale versions ⇒ no commit, no comment). winget installation bypasses the SmartScreen prompts (the default community source rewrites MOTW to the trusted zone) — the only no-code-signing channel that does.
- **One-shot release: `./release.sh <ver>`** (repo root, run from Git Bash). Automates the checklist above: portable build → installer + fixed-name copy + `SHA256SUMS.txt` → version bump (`src/version.h`, both README badges, `winget/<ver>/` cloned from the newest existing version with `InstallerSha256`, `ReleaseDate` and the URLs rewritten) → commit → push → lightweight tag → GitHub Release with all three assets → live verification (`releases/latest` must redirect to the new tag, and the fixed-name installer is re-downloaded and hashed against the local build). It also rewrites the SHA-256 inside `dist/RELEASE_NOTES_v<ver>.md`, since that number only exists after the build. `--dry-run` runs the entire pipeline and then restores the version bump, so it is the only safe rehearsal; `--skip-build` is rejected together with a version change because it would package the previous build under the new number. Pushes optionally fall back to `PROXY` (empty by default) when a direct attempt fails. Other flags: `--yes`/`-y` (no confirmation), `--no-winget` (skip manifest generation), `--no-winget-pr` (generate but do not submit), `--no-verify-download`, `--notes`, `--title`, `--proxy`. After the GitHub Release is created it calls `winget/submit.sh <ver>` (previous bullet) — that failure is a warning, not a release failure, since the artifacts are already public; rerun the script by hand. `*.sh` is pinned to LF in `.gitattributes`: Git for Windows defaults to `core.autocrlf=true` and a CRLF shebang breaks bash.
- `.github/workflows/release-installer.yml` builds the portable installer in GitHub Actions (MSYS2 MinGW64 + Inno Setup; the `OS=Windows_NT` export is required there too, and `OPT_FLAGS` is overridden for portability). It also writes `dist/SHA256SUMS.txt` (uploaded with the installer artifact) — attach it to the release. It exists both for reproducible releases and because SignPath's free OSS signing requires the signed artifact to come from a trusted build system — locally built installers cannot be submitted. SignPath steps are gated on the repo variable `SIGNPATH_ENABLED`; re-verify action input names at docs.signpath.io when enabling after approval. `CODE_SIGNING_POLICY.md` (root) is a SignPath application precondition — keep it accurate once signing is live. The signed path regenerates `SHA256SUMS.txt` from the signed exe before uploading; never attach the unsigned hashes to a signed release.

## Windows specifics (easy to get wrong)

- `sender` links as a **console** subsystem app (logs + interactive prompts + Ctrl+C). `receiver` and `app` link with `-mwindows` (GUI, stdout discarded).
- `res/admin.manifest` declares **PerMonitorV2 DPI awareness** for both sender and app. The sender must be DPI-aware: in a DPI-unaware process Windows virtualises `GetSystemMetrics`/`GetMonitorInfo`/GDI capture coordinates (a 3840x2160 VDD is reported as 2560x1440 at 150 %), which silently turns the receiver-matched extend path into an upscaled stream. Don't remove it — the GUI's `g_uiScale` assumes per-monitor awareness too.
- **Stitch (software KVM) input plumbing** — `kvm.cpp` is Windows-only (`kvmSupported()` is inline in `kvm.h` so `app` needs no link). Controller: `WH_MOUSE_LL`/`WH_KEYBOARD_LL` + a hidden top-level window with `RIDEV_INPUTSINK` Raw Input; **never do socket I/O inside a hook** (overrunning `LowLevelHooksTimeout` silently unhooks it) — events go through an SPSC ring to a drain thread, which posts a disconnect back to the message loop. Edge crossing must use `WM_INPUT` relative deltas: once the cursor is clamped at the virtual-desktop edge the hook's `pt` stops changing. Nothing but the ring push may run inside a hook callback: `ShowCursor`/`SetCursorPos`/`std::cout` (panic hotkey, mode changes) are deferred to the message loop with `PostMessage`; the button *state* table is updated in both Local and Remote (a press or release that straddles a mode switch would otherwise be replayed as a phantom drag or never re-armed), and both hooks pass `*_INJECTED` input through untouched instead of forwarding it. Target: per-session topmost consent `MessageBoxW` (default No, 30 s auto-dismiss + shutdown watcher) then `SendInput` (absolute + `MOUSEEVENTF_VIRTUALDESK`, scan-code keys). Both roles poll the caller's `g_running` as **true = running**. `-luser32` is in `SENDER_LIBS`/`RECEIVER_LIBS` for exactly this file. Elevation: a standalone `bin/receiver.exe` is not elevated, so injection stops at its integrity level (UIPI — no input into elevated windows, no secure-desktop input); launched from `app.exe` it inherits the GUI's `requireAdministrator` token and can reach elevated windows, which is why the consent prompt matters. This is a behavior difference worth stating in the user docs, not a bug to "fix" by de-elevating a child Windows cannot easily de-elevate.
- SDL2_ttf needs a CJK font at runtime; `app.cpp` walks an ~11-path candidate list (`msyh.ttc`/`simhei.ttf`/NotoSansCJK/wqy/…) and exits with an error if none is found. Caveat: the list also contains non-CJK `DejaVuSans.ttf`, so on a machine with no CJK font the probe can "succeed" via DejaVu and render tofu instead of erroring.
- The runtime DLL closure must sit in `bin/` next to the exes (already there). After adding a library, verify with `ldd bin/<exe>.exe` and copy missing DLLs into `bin/`.
- Extend mode needs the MttVDD indirect-display driver installed once (`vdd/install_vdd.ps1`). The virtual display lifecycle lives in `src/vdd.cpp`/`vdd.h` (`vddStartup`/`vddShutdown`/`vddForceDetach`, CCD API + SetupAPI device enable/disable) and is linked into both `sender` and `app`. The VDD mode list is read by the driver **once at start-up** from `vdd_settings.xml` (registry `SettingsPath`/`VDDPATH` override first, else `%SystemRoot%\System32\drivers\UMDF\vdd_settings.xml`); a size absent from that list cannot be applied. `vddEnsureMode()` can append the receiver's exact size (numeric-only and even, bounded 320x240..7680x4320, session mutex, pristine `.mivara.bak`, unique temp + `ReplaceFile` which keeps the System32 ACL, in-memory rollback, re-read verification) but refuses to touch the file while any VDD CCD path is ACTIVE — that would yank a display a live session owns; `vddStartup(..., reloadFirst=true)` then does one disable/enable cycle (never while a path is active) so the UMDF stack re-reads the file; otherwise `vddStartup` enumerates the exposed modes and uses the closest aspect. The receiver aspect-fits the stream (black bars) instead of stretching, so a residual mismatch is never distortion. **Never break the Ctrl+C graceful path** — a hard exit leaves the virtual display attached to the user's desktop. Covered exit paths: normal end, send failure, Ctrl+C, console-window close (detaches inside the `CTRL_CLOSE_EVENT` handler), `atexit`. The GUI stops the sender by sending Ctrl+C (`GenerateConsoleCtrlEvent`), hard-kills only after an 8 s timeout, and calls `vddForceDetach()` as a safety net after a hard kill.
- A CCD detach alone leaves the monitor visible in Settings > Display — teardown MUST also disable the PnP device (hardware ID `Root\MttVDD`, instance `ROOT\DISPLAY\000x`; match on hardware IDs, never touch other vendors' virtual display adapters). Enabling/disabling requires elevation: `sender` and `app` embed a `requireAdministrator` manifest via `res/admin.rc` + `res/admin.manifest` (windres, see makefile `RES_ADMIN`). `receiver` is not elevated. Disable failure degrades gracefully (warn + CCD-only). A disabled device has no CCD path — `vddStartup` must enable the device **before** the `vddInstalled()` gate.
- `scripts/*.bat` are convenience wrappers that launch `bin/` exes; `启动投屏发送.bat` takes the receiver IP as an argument.

## Architecture (actual wiring)

| File | Role |
|------|------|
| `src/sender.cpp` | capture (GDI/X11/CoreGraphics), handshake, streaming, runtime reconfigure (SETP). Extend mode probes the receiver's display size (zero-dimension HsRequestV2) before sizing the VDD. |
| `src/vdd.cpp/.h` | Windows virtual display (MttVDD) lifecycle: enable/disable PnP device (SetupAPI) + attach/detach/position via CCD API, mode enumeration/closest-aspect fallback, and opt-in exact-mode append to `vdd_settings.xml`. Linked into sender + app. |
| `src/receiver.cpp` | SSDP broadcast, SDL2 fullscreen render (aspect-fit, never stretch), per-connection display-size refresh + zero-dimension probe fast path, hosts the sidecar services (8082/8083/8084) |
| `src/kvm.cpp/.h` | 拼接 (stitch) software KVM on TCP 8084: controller = low-level hooks + Raw Input edge detection + SPSC ring → socket; target = per-session consent dialog + `SendInput` injection. The peer may sit on any of the four sides (controller-only state, switchable mid-session; `kvmSideKey`/`kvmSideFromKey` are **inline in the header** because `app` includes it but never links kvm.cpp). Windows only; sender/receiver/app share the header (app only needs `KVM_PORT`/`kvmSupported`), never the video/VDD path |
| `src/discover.cpp/.h` | SSDP discovery engine (UDP 1900); parses SSDP `NAME:` into `DiscoveredDevice.name` |
| `src/gpu_accelerate.c/.h` | remote CPU offload protocol (RLE compress / color convert) served on 8082 — only used by the RLE codec path |
| `src/ports.cpp/.h` | remote port inspector on 8083 (LIST/GET/KILL) |
| `src/proto.h` | protocol v2 shared by sender/receiver: HsRequestV2/HsResponseV2, CodecId, control packets |
| `src/codec.h/.cpp` | FFmpeg Encoder/Decoder (H.264/H.265/AV1). Linked into sender + receiver only (app is FFmpeg-free) |
| `src/config.h/.cpp` | GUI settings (%LOCALAPPDATA%\\Mivara\\config.ini), key=value (incl. `auto_start` → Task Scheduler `Mivara` job, `auto_receive`, `theme` = light\|dark\|system, `extend_res` = auto\|WxH, `vdd_mode_write` = ask\|always\|never, `stitch_side` = left\|right\|top\|bottom) |
| `src/history.h/.cpp` | connection history (history.ini, cap 20, newest first) |
| `src/theme.h/.cpp` | GUI palette: light/dark token sets + follow-system resolution (`themeTick`, Windows registry `AppsUseLightTheme` polled every 2 s; macOS/Linux sampled once per process — the popen is never repeated, so at most one UI-thread sample is ever taken, which lands on the first 跟随系统 click if the app was launched in light/dark). app.cpp colours come from `theme()`; the only exceptions are the two mode-independent constants in theme.h (`DANGER_SOLID`, `SWITCH_ON`), plain white (toggle knob, the danger-button label, the chip/banner hover washes) and plain black (the danger button's hover wash). |
| `src/app.cpp` | SDL2 + SDL2_ttf GUI launcher: header (wordmark + 更新 button, present only while a release is waiting + icon appearance switcher: sun 亮色 / moon 暗色 / monitor 跟随系统) over a left nav (主页/设置) + session flows and connection history inside 主页 (history rows under the 接收/发送 cards; no separate history tab); SSDP search, device list (投屏/扩展/拼接), manual IP, settings; 拼接 opens a modal four-way direction chooser (`g_stitch_ask` + `BTN_STITCH_SIDE_*`, drawn as an overlay and enforced as a modal in both `buildButtons` and `onButton`), and a running stitch session shows the same four choices as `BTN_STITCH_SWITCH_*` chips in the status panel (sent as `STITCH|side=…`); spawns sender/receiver as child processes with hidden console + stdout pipe (STAT| status panel + log window) and a **stdin pipe carrying `SETP|` / `STITCH|` lines**. Layout lives in the `shared layout` macro block — `buildButtons()` (hit rects) and `renderScreen()` (painted rects) both read it, so a control can never be drawn in one place and clicked in another; keep it that way. Appearance is the only setting with two controls (header + 外观 card), so its ids are matched against the `kThemeIds` table, never derived by subtracting a base: a `(id >= BTN_SET_THEME_BASE) ? …` range test is true for the header ids too (8020 ≥ 7070) and once indexed `modes[950]` out of bounds, which silently made every header click fall back to 亮色. **Display scale (`g_uiScale`)** — the layout is a fixed 880×700 logical grid and SDL makes the process per-monitor DPI aware, so without this the UI is drawn 1:1 and lands 25 % small on a 125 % display with one-pixel CJK strokes (the "jagged text" complaint). main() resolves it once (quarter steps, capped to the usable screen), the window is created at `uiPx(WIN_*)`, `SDL_RenderSetScale` scales every shape, fonts open at `uiPx(size)` and text blits itself in device pixels (`drawTextPx`), pointer coords are divided by `uiCoord()` at the event boundary (`floor`, not `lround` — the renderer paints a scaled rect as `[floor(x*s), ceil((x+w)*s))`, so rounding to nearest shifts every hit rect a pixel left at 2× and makes an edge-sharing chip select its neighbour), and `fitText()` compares in device pixels. Any new layout constant stays logical; any new direct pixel measurement must go through `uiPx`/`uiCoord` or it will be wrong at ≠1×. **Shape antialiasing** — SDL's shape primitives have no AA, and `SDL_RenderSetScale` scales a primitive's *coordinates* but not its *thickness*, so at 1.25× the shipped build drew the toggle pills, the warning triangle and every 1px hairline as striped scanline bands on the D3D9 backend. `fillCircle` / `fillRoundRect` / `drawRing` / `drawGlyph` / `glyphWarning` therefore blit a cached coverage mask (`g_masks`, per-renderer, dropped in `closeLogWindow` and at exit) instead of calling the primitives. Invariants: masks are baked by running the **shipped rasteriser** (`fillCircleRaw` / `fillRoundRectRaw`, kept verbatim as `*Raw`) at `MASK_SS`× by multiplying the *geometry*, never by setting the render scale — the software backend scales a `RenderDrawLine`'s coordinates but not its thickness, so a scaled scanline combs the shape; a glyph body's stroke width is hardcoded in canvas pixels, so **glyph masks bake at logical resolution** and are upscaled with `SDL_ScaleModeLinear` (baking them supersampled shrinks every stem to a hairline); AA passes run inside a `ScaleScope` (save → force 1.0 → restore) because `SDL_RenderCopyEx` honours the ambient scale; `fillRoundRect`'s corner-mask blits must abut the edge bands exactly, never overlap; every mask's transparent pixels must carry **white** RGB — `MaskCanvas` clears to `(0,0,0,0)`, so a mask must be built through `coverageFrom` (which forces `0x00FFFFFF`) rather than uploaded raw, because the linear upscale interpolates RGB as well as alpha and a black transparent pixel multiplies the glyph by its own coverage a second time, greying every antialiased edge; and each shape must be baked about the **centre of the output pixel's supersample block** (`R * MASK_SS + MASK_SS / 2`), not the block's first canvas pixel, or the whole shape lands a fraction of a device pixel up-left (the disc's coverage centroid sits 0.13 device px from the pre-AA rasteriser's placement after this correction, 0.38 before). Note the placement convention the masks must preserve: a disc at logical `(cx, cy)` is centred on **pixel index** `uiPx(cx)`, i.e. continuous `uiPx(cx) + 0.5` — matching the pre-AA `fillCircleRaw` — which is a constant 0.5 px off jagprobe's analytic "ideal centre", so that probe's absolute disc RMS is biased and must not be read as a placement error. Any new shape drawn with a raw SDL primitive will be jagged at ≠1× — route it through a mask. Extend launches ask once (native MessageBox) before the sender may append the receiver's mode to `vdd_settings.xml`; the answer is persisted as `vdd_mode_write` in config.ini. |
| `src/update.h/.cpp` | app-only update check + in-app updater (settings 更新 row, home banner, header button, nav dot). Check = one HTTPS GET of `releases/latest`, version from the 302 `Location` — **never `api.github.com`** (60/h per unauthenticated IP). Windows download lands in `%ProgramData%\Mivara\Updates`, which is taken over with owner=Administrators + a **protected** DACL (SYSTEM/Admins full, Users read/execute, inheritance dropped) and then read back to confirm; the installer is verified against the release's `SHA256SUMS.txt` (fail-closed) and re-hashed right before launch. POSIX builds only check + open the release page. Links `-lwinhttp -lbcrypt -ladvapi32`. **One-click path:** the header button (`BTN_HDR_UPDATE`, ghost hit area painted by `drawHeader`) sets `g_upd_auto_install`, and the `updateTake()` completion hook runs `startInstall()` itself once the package verifies — except while a sender/receiver child is live, where quitting would kill the session; then the button turns green and waits for a second click. Only the header button arms that flag: 下载更新 in the 更新 card still stops at 立即安装. |
| `src/version.h` | single version source (`MIVARA_VERSION`, bare `X.Y.Z`) consumed by C++ **and by the Inno preprocessor** — keep it comment-free. |

- `ports.cpp` has a hidden `main()` behind `-DPORTS_MAIN` — can be compiled standalone as a port-inspection CLI. The makefile never sets this flag; don't be confused by two `main` functions in the tree.
- `sender` CLI: `sender [ip] [port] [--mode mirror|extend|stitch] [--stitch-side left|right|top|bottom] [--codec auto|h264|h265|av1|raw|rle] [--hw 0|1] [--bitrate <kbps>] [--quality 0-51] [--fps <n>] [--scale <pct>] [--chroma 420|444] [--extend-res auto|WxH] [--vdd-add-modes 0|1]`. `--mode` skips all interactive prompts — the GUI depends on it (an unknown value is an error, never a fall-through to the prompt). Keep it working non-interactively. `--stitch-side` is where the peer sits (default `right`); an unknown value is a hard error. `--mode stitch` is resolved before discovery so the direct-connect probe uses TCP 8084, and it returns after `kvmRunController()` — no capture, VDD, codec or 8081/8082/8083 traffic — but it **does** start the stdin reader first, because the GUI switches sides with `STITCH|side=…` lines (the streaming path starts its own reader later; do not start it twice). Extend mode with `--extend-res auto` (the default) probes the receiver's current display size before creating the VDD; `--vdd-add-modes 1` permits appending a missing exact mode to the driver's `vdd_settings.xml` (the GUI asks once and passes it only after consent). After streaming starts, a reader thread consumes stdin lines (`SETP|k=v|…` / `PING`) — stdin may be a GUI pipe, so never treat it as an interactive prompt channel once the loop begins.
- File-size orientation: `app.cpp` (~4400 lines) is by far the largest source, then `sender.cpp` (~1830), `ports.cpp` (~1825) and `kvm.cpp` (~1660).
- `receiver`'s 8082/8083 sidecar services are cooperatively stoppable: both take a stop callback (`gpu_stop_fn` / `ports_stop_fn`, receiver passes `mivara_service_should_stop` which reads the single `g_running` flag), gate `accept` behind a 1 s `select()`, and use stop-aware `recv`/`send` wrappers so an idle persistent client cannot pin the join. Accepted sockets are switched to non-blocking after `accept` — a select-for-write only promises *some* space, so a blocking `send()` of a multi-MB response could otherwise ignore the stop flag for the whole TCP retransmission timeout; `EAGAIN`/`EWOULDBLOCK` loops back through the 1 s wait. `ports_service_run` also tracks its POSIX worker threads and waits up to 2 s for them before returning (logging if any remain). The only work that can delay shutdown beyond ~1–2 s is an in-flight `collect_ports()` (Windows table walk / macOS `lsof`) or a single compute op — the stop flag is checked on the next I/O wait. This makes `main`'s joins complete, so the final stats flush, socket close and shutdown summary are reachable. The GUI's graceful stop still does not apply in the default hidden-console launch: `receiver` is a GUI-subsystem exe with no console, so `stopChild`'s `AttachConsole` fails and it is TerminateProcess'd immediately — the 8 s Ctrl+C-then-kill path is for the console-subsystem `sender` (POSIX GUI: SIGINT → 3 s → SIGKILL). With `show_status_console=1`, an in-session SDL quit/ESC and POSIX SIGINT now reach full cleanup; `gpuStatsWriterThread` sleeps in 1 s chunks so it cannot overrun the 8 s wait.
- The 8083 port inspector has **no authentication** — any LAN peer that can reach the port can LIST/GET/KILL receiver-side processes. Keep it LAN-only.
- The 8084 stitch listener (`kvmServiceRun`) follows the same cooperative pattern but **polls the `running` flag, not a stop flag**: `kvmRunController`/`kvmServiceRun` take `std::atomic<bool>` where **true = keep running** (both callers pass `g_running`). Getting this inverted makes the listener exit at start-up while 8081/8082/8083 keep working — the symptom is a missing 8084 in `netstat` plus `[kvm] stitch listener stopped` right after `… on TCP 8084`. Every exit path joins the thread from `main`. One controller at a time: the session runs on its **own thread** so the listener stays responsive — while it is active, a second controller is accepted and answered `KVM_ERR_BUSY` immediately instead of sitting in the accept backlog for the whole session. Read its hello before replying: closing a socket with unread received data makes Windows send an RST, which discards the BUSY reply and surfaces as `WSAECONNRESET` on the controller. Both ends enable TCP keepalive (15 s idle, 3 s interval): a KVM is silent whenever the user is idle, so a controller that loses power or Wi-Fi never sends a FIN, and without keepalive the session thread would wedge the only slot forever (with the peer's keys possibly still held down). The hello has a 5 s deadline, and an **explicit** refusal suppresses further consent prompts **from that source IP** for 60 s (keyed on the address, so one hostile host cannot auto-deny every other controller on the LAN); an unanswered 30 s box is a timeout and arms no cooldown. The consent watcher also `select`s the session socket and dismisses the box as soon as the controller disconnects — otherwise the sole slot stays busy until the 30 s timeout and the reconnect is answered BUSY; a peer that hangs up during the prompt gets a 3 s backoff (recorded per source in a bounded 8-entry table **and** in one global tick, so a source that rotates addresses only bypasses the per-source half; a non-blocking FIN check skips the dialog entirely and the wait polls the socket so a vanished peer frees the slot at once), and two dialogs are never shown less than 1.5 s apart regardless of source, so connect-then-close cannot flicker the topmost dialog. Only a real `IDNO` counts as a refusal: `MessageBoxW` returning 0 (no interactive window station, out of resources) must not arm the 60 s cooldown — it is logged as a prompt failure and answered `KVM_ERR_DENIED` without a cooldown. Held-input bookkeeping stores the exact scan code and extended flag that were injected and releases those on the way out — never a VK→scan reconstruction, which does not round-trip for numpad Enter, media keys or a differing layout. Screen metrics are agreed at handshake; a mid-session resolution change on the target is not renegotiated (reconnect). Consent is a topmost `MessageBoxW` (default No, 30 s auto-dismiss, force-closed by a watcher thread on shutdown) — never move it to the accept thread's critical path without keeping that force-close, or receiver shutdown hangs on a modal dialog. **Posting `WM_CLOSE` / `WM_SYSCOMMAND(SC_CLOSE)` to a MessageBox does not close it** (verified on Windows 11 26200: the box stays up forever, so an auto-dismiss built on it silently never fires and shutdown hangs); the watcher enumerates the owner thread's `#32770` windows with `EnumThreadWindows` and posts `WM_COMMAND(IDNO)` instead, which is equivalent to clicking the default No and returns `IDNO`. No encryption, no peer authentication: the per-session human confirmation is the only gate.
- The updater is self-contained and must stay that way: it never touches the protocol, the VDD path, the children or the config, and the worker thread never calls SDL/`logPush`/`configSave` (the UI polls `updateTake()` once per frame). Invariants to preserve: only `github.com/wzy-777/Mivara` is contacted (User-Agent only, nothing uploaded); redirects are followed only for downloads and the **final URL must land on `github.com`/`*.githubusercontent.com` over HTTPS or no body byte is read**; the tag is validated to a fixed charset before it builds a URL or file name; in-app install is fail-closed on a missing `SHA256SUMS.txt` entry. `src/update.cpp` carries a hidden CLI behind `-DUPDATE_TEST_MAIN` (cf. `-DPORTS_MAIN`): `unit` / `check` / `download <tag>` / `hash <file>` — the makefile never sets the flag.

## Protocol constants (defined in `src/proto.h`)

- Handshake over TCP 8081 (**protocol v2**, all u32 network byte order, magic `0x54564853` 'TVHS'):
  - Request (sender→receiver) `HsRequestV2` **48 bytes**: magic, version=2, width, height, fps, mode, codec, codec_flags, bitrate_kbps, quality, gop_frames, reserved.
  - Response (receiver→sender) `HsResponseV2` **36 bytes**: magic, version, recv_width, recv_height, status, codec, codec_flags, reserved[2].
  - `mode`: 0 = mirror, 1 = extend. `codec`: 0=raw 1=rle 2=h264 3=h265 4=av1. `status`: 0=ok 1=version 2=codec 3=dims 4=decoder 5=legacy.
  - Receiver peeks 4 bytes first: non-TVHS magic ⇒ legacy peer, explicit error (no black screen). Old 16-byte handshake is rejected.
  - **Display-size probe (no version bump):** a normal `HsRequestV2` with `width=0 && height=0` asks only for `HsResponseV2.recv_width/recv_height`; the receiver answers with `status=HS_ERR_DIMS` and returns before creating a window or a decoder (it does one SDL_Init/SDL_Quit to query the display mode, so the reply is in physical pixels). No window appears and no client stats are recorded. Probe replies require `version == 2`. Extend mode uses it to size the VDD before the real handshake.
- Stream packets: `[u32 pkt_size][payload]`; control = `u32 0xFFFFFFFF` + `u32 ctrl_type` + body. `CTRL_RESIZE=1` body = HsRequestV2; `CTRL_FORCE_IDR=2` / `CTRL_EOS=3` body empty; `CTRL_RECONFIG=4` body = HsRequestV2 (runtime param change — receiver re-opens the decoder and sets `skip_until_key`, see the shared resize/reconfig handler in receiver.cpp).
- Coded payload = one access unit per packet (annex-B / OBU). Raw/RLE unchanged. 8082 remote RLE is connected **only** while `codec=rle` (connect/disconnect follows runtime codec switches).
- STAT| machine-readable status lines on stdout (parsed by the GUI): `STAT|k=v|k=v|...` with keys t/frames/fps/kbps/codec/hw/mode/src/dst/quality or `event=start|stop|error|applied|pong|stitch` + `msg=` (stitch adds `state=waiting|local|remote` and `side=left|right|top|bottom`; the GUI renders the state in `drawStatPanel` and the side as its four-way switch). The parser replaces its state per line, but not every line is a full snapshot: only periodic lines and `event=applied` carry the full key set — `start`/`stop`/`error`/`pong` carry subsets (sender `error` = `msg=` only; the receiver emits its own `start`/`stop`/`error`/`resize`/`reconfig` variants). The GUI special-cases event lines; check `parseStatLine` in app.cpp before changing emitter key sets.
- GUI→sender stdin line protocol (runtime reconfigure): `SETP|codec=…|hw=…|bitrate=…|quality=…|fps=…|scale=…|chroma=…` (any subset; keys map to the CLI flags; numeric values must be whole decimal numbers — parse with a strict whole-token check, never `atoi`; all-or-nothing validation, reply `STAT|event=applied|…` or `STAT|event=error|msg=bad_value_*`). `STITCH|side=left|right|top|bottom` switches a running stitch controller's edge (applied by the message loop within one 50 ms tick; hands control back first). `PING` → `STAT|event=pong`.
- Ports: 1900/udp SSDP, 8081/tcp video, 8082/tcp compute offload (`GPU_ACCEL_PORT`), 8083/tcp port inspector (`PORTS_SERVICE_PORT`), 8084/tcp stitch KVM (`KVM_PORT`, `kvm.h`).
- **Stitch channel (8084, protocol independent of v2):** `KvmHello` (16 B, magic `0x4D564B31` 'MVK1'; `reserved[0]` = the peer's side from the controller's viewpoint + 1 (1 left / 2 right / 3 top / 4 bottom), used only to word the target's consent dialog — 0/unknown means right, so a zero-filled hello from an older build is not misread as "left") → `KvmReply` (32 B: status 0 ok / 1 version / 2 denied / 3 busy + target virtual-desktop x/y/w/h) → `KvmEvent` (16 B: type 1 move / 2 button / 3 wheel / 4 key / 5 release-all). All `uint32` network byte order. The side itself is controller-only state (the target injects absolute coordinates), so switching needs no message. `HsRequestV2.mode` stays 0/1 — stitch never touches 8081, and `handleClientConnection` normalises any other mode to mirror.
- SSDP discovery: sender probes **per local NIC** over 3 rounds (~100 ms apart), each sending multicast + 255.255.255.255 + a directed per-NIC subnet broadcast (enterprise nets often drop multicast). Replies are keyed on the **datagram source address**, with the LOCATION IP probed only as a fallback (multi-homed receivers may advertise the wrong NIC). Receiver's LOCATION uses `getLocalIPForPeer(requester)` (same-subnet NIC). Receiver advertises `NAME: <hostname>`.
- Windows `SO_RCVTIMEO`/`SO_SNDTIMEO` take DWORD milliseconds, not `struct timeval` (POSIX). Passing a timeval silently gives ~5 ms timeouts.
- Sender and receiver must be the **same binary version** (protocol v2). Mismatched builds fail the handshake with an explicit error — never silently black-screen.
