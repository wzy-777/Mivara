画质与编码

这些选项决定画面在发送端如何压缩、以多大码率和帧率传输，以及接收端看到的清晰度与延迟。 本页说明「设置 → 画质与编码」中的每一项，并给出按场景的选择建议。

设置位置：设置 → 画质与编码 生效方式：点「保存设置」后生效 会话中可热更新，无需断开重连

编码方式

编码方式决定压缩算法。它只影响「投屏 / 扩展」的画面传输；「拼接」只共享键鼠、不传画面，与这些设置无关。

自动

推荐 当前等同 H.264

是什么由程序选择编码方式。目前的实现中，「自动」与「H.264」使用完全相同的逻辑：优先硬件编码，失败时回退软件编码。

怎么选不确定时选它即可。保留这个选项是为了以后能按两端的设备能力自动挑选编码。

H.264

默认

是什么兼容性最好、解码最轻的编码。发送端优先使用 GPU 硬件编码（NVIDIA NVENC / Intel QSV / AMD AMF，Linux 为 VAAPI），硬件不可用时回退软件 libx264。接收端使用软件解码，H.264 的软解负担在常见编码里最低。

怎么选绝大多数情况都用它：办公、网页、视频、游戏都合适。老机器、老显卡、或者不想折腾时，它是最稳的选择。

H.265 / HEVC

省带宽

是什么同码率下通常比 H.264 更清晰，适合带宽有限或想降低网络占用的场景。发送端同样硬件优先（NVENC / QSV / AMF / VAAPI），回退软件 libx265。

怎么选两端机器都不太老、并且带宽紧张时选它。代价是编码和解码负载更高；较老的显卡可能没有 H.265 硬件编码，较老的接收端 CPU 也可能跟不上高分辨率。出现卡顿就换回 H.264。

AV1

压缩率最高 硬件要求高

是什么当前压缩率最高的编码，静态桌面和文字内容尤其省带宽。硬件编码需要较新的 GPU（例如 RTX 40 系、Intel Arc、RX 7000 系及更新型号）；没有硬件编码时使用软件 SVT-AV1，编码很吃发送端 CPU。接收端目前只能软件解码，4K 或高帧率下负担最重。

怎么选发送端有 AV1 硬件编码、并且确实需要省带宽时再选。AV1 的 CRF 刻度与 H.264 不完全可比：想省带宽可从 30–35 起步，追求画质用 23–28。老机器、高分辨率或高帧率场景不建议。

原始

带宽极大

是什么不压缩的 RGB 画面直接传输，不经过编码器：完全无损、没有编码延迟，但带宽需求极高。1080p60 约 370 MB/s，而千兆网实际只有约 110 MB/s，远远不够。

怎么选只建议在 2.5G / 10G 有线局域网、低分辨率或本机测试时使用。此模式下「画质」「码率」「色度」「缩放」都不生效，帧率上限仍然有效。

RLE

无损压缩

是什么逐帧无损压缩，桌面文字和 UI 通常能省 30–70% 带宽；照片和视频的压缩率低，带宽仍远高于 H.264。压缩可以交给接收端 CPU 完成，发送端负担很小；如果接收端的压缩服务不可用，会退回未压缩发送。

怎么选想要零压缩损失、同时发送端 CPU 很弱时，可以在有线局域网里使用。与「原始」一样，「画质」「码率」「色度」「缩放」不生效（帧率上限有效）。

画质与流畅度

下面三项只对编码流（H.264 / H.265 / AV1）有意义；「原始」和「RLE」不走编码器。

画质 (CRF)

0–51 · 越小越清晰

是什么压缩强度的刻度。数字越小，画面越清晰、占用带宽越高；数字越大，越省带宽、细节丢失越多。默认 23。

怎么选文字 / 代码为主用 18–22；日常 23；带宽紧张用 26–30。它只在「码率 = 0（质量模式）」时生效；码率大于 0 时会被码率模式取代。不同编码器的内部实现不同（x264 CRF、NVENC CQ、QSV global_quality、AMF QP），所以这个数字适合在同一编码方式内部比较。

帧率上限

1–240 · 默认 60

是什么发送端每秒最多采集、编码并发送多少帧。降低它可以同时减少带宽、CPU 和 GPU 占用；提高它只对高速运动画面有明显意义。

怎么选办公和视频 30–60；游戏和高刷屏用 120–144，或与显示器刷新率一致。帧率上限只是上限，实际帧率还取决于画面变化和机器性能。

码率

0 = 质量模式

是什么限制每秒传输的数据量，单位 kbps，步进 1000。设为 0 表示不限制，由「画质」控制压缩强度，画面复杂时自动多用带宽；设为大于 0 时，编码器会尽量贴近目标码率（NVIDIA 硬件编码为恒定码率，其他编码器为受限码率），此时「画质」不生效。

怎么选局域网优先用 0（质量模式），画质更稳定。网络有限、多人共用或需要可预测占用时再设上限：1080p60 桌面约 8–15 Mbps，1080p30 约 4–8 Mbps，4K60 约 25–40 Mbps；游戏和高速运动需要更高。画面出现块状模糊时，先提高码率或降低帧率。

图像细节

缩放

100% / 75% / 50%

是什么发送端先把画面缩小到对应比例再编码，接收端再放大到窗口大小。缩放能显著降低带宽和两端的编解码压力，但文字和小图标会变糊。

怎么选平时 100%。4K 桌面投到 1080p 接收端、或 Wi-Fi 带宽不足时可用 75%。50% 只适合看视频或远距离观看，不适合阅读文字。「原始 / RLE」不使用缩放。

色度

4:2:0 / 4:4:4

是什么色度决定颜色信息的采样精度。4:2:0 把颜色分辨率减半，兼容所有硬件编码器，是默认值；4:4:4 保留完整颜色细节，彩色小字和子像素抗锯齿边缘更锐利，但带宽和接收端 CPU 略高。

怎么选默认 4:2:0。以文字、代码为主并且追求锐利度时，可以尝试 4:4:4。

4:4:4 只对软件 H.264 / H.265 编码器真正生效。开启硬件加速时，GPU 编码器仍按 4:2:0 编码；AV1（软件 SVT-AV1）也不支持 4:4:4。 要真正启用：关闭右侧「传输」卡片里的「硬件加速」，编码方式选 H.264 或 H.265，再选 4:4:4。若出现无法连接或画面异常，换回 4:2:0。

硬件加速（右侧「传输」卡片）

与画质设置相关

开启优先使用 GPU 编码（NVENC / QSV / AMF / VAAPI），不可用时自动回退软件编码。延迟低、发送端 CPU 占用小，适合游戏、视频和高帧率；但 GPU 编码固定使用 4:2:0，不能启用 4:4:4。

关闭强制软件编码，CPU 占用更高，但可以使用 4:4:4，也不受显卡驱动和 GPU 编码器限制。文字优先、机器性能足够时选它。

显卡驱动过旧可能导致硬件编码失败。遇到「编码器无法打开」或画面异常时，可以关闭硬件加速，或先升级显卡驱动。

常见问题

改完设置为什么没有立刻生效？

这些选项需要点「保存设置」才会写入并应用。会话进行中保存后通常几秒内热生效，连接不会断；切换编码方式、缩放或色度时，接收端需要重建解码器，可能瞬断一两帧，属于正常现象。

选了 4:4:4，为什么画面没有变化？

开启「硬件加速」时，GPU 编码器固定按 4:2:0 编码，4:4:4 不会生效。请关闭硬件加速，并把编码方式设为 H.264 或 H.265。AV1 的软件编码器也不支持 4:4:4。

画面卡顿、花屏或偶尔断连怎么办？

先把编码方式换回 H.264，帧率降到 30，缩放设为 75%，并给码率设一个上限（例如 1080p 用 8000）。优先使用千兆有线或 5 GHz Wi-Fi，避免 2.4 GHz 和拥挤的信道。如果仍然异常，检查两端机器的 CPU/GPU 占用和显卡驱动。

怎样降低带宽占用？

最有效的是降帧率（60 → 30）和缩放（100% → 75%）；其次是换 H.265 或 AV1、把画质调到 26–30，或直接设置码率上限。避免使用「原始」和「RLE」，它们的带宽需求远高于编码流。

接收端 CPU 占用太高怎么办？

接收端始终是软件解码，编码方式越新越重。优先选 H.264（解码最轻），降低分辨率和帧率，避免在高分辨率、高帧率下使用 AV1。缩放也会降低接收端的解码和显示压力。

为什么「原始 / RLE」调画质、码率、色度没有用？

这两种方式不经过 H.264/H.265/AV1 编码器，所以画质、码率、色度和缩放都不参与。它们只受帧率上限和网络带宽影响。

换了 H.265 或 AV1 后连不上、黑屏或很卡？

可能是接收端性能不足或解码器不可用。先换回 H.264 验证连接；确认两端的 Mivara 都是较新的版本。较老的接收设备在 4K 或高帧率下尤其容易跟不上。
