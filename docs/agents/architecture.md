# Architecture maintainer guide

Authoritative guidance for source wiring, command-line behavior, service lifecycles and app/updater invariants. Read the relevant sections before changing those areas.

## Architecture (actual wiring)

| File | Role |
|------|------|
| `src/sender.cpp` | capture (GDI/X11/CoreGraphics), handshake, streaming, runtime reconfigure (SETP). Extend mode probes the receiver's display size (zero-dimension HsRequestV2) before sizing the VDD. Windows uses DXGI Desktop Duplication when the output can be duplicated (see `src/capture_dda.cpp`; GDI fallback, `MIVARA_CAPTURE=gdi` opt-out). For a hardware encoder (NV12) the duplicated BGRA goes straight to swscale (`encodeBGRA`, no intermediate BGR24 pack); a software encoder (YUV420P) and RAW/RLE still get the packed BGR24/RGB24 path, because swscale's BGRA→YUV420P kernel differs from BGR24 by up to 29 levels. |
| `src/capture_dda.cpp/.h` | Windows-only DXGI Desktop Duplication backend (sender-only, `-ld3d11 -ldxgi`): GDI-matched output, D3D11 staging copy, cursor composited into a top-down DIB, desktop/cursor-change detection, ACCESS_LOST backoff. Measurements and edge cases: [windows.md](windows.md). |
| `src/vdd.cpp/.h` | Windows virtual display (MttVDD) lifecycle: enable/disable PnP device (SetupAPI), independently sourced CCD attach/detach/position with non-MTT layout preservation and read-back verification, mode enumeration/closest-aspect fallback, opt-in exact-mode append to `vdd_settings.xml`, and cross-session placement memory (side/gap/offset in `%LOCALAPPDATA%\Mivara\extend.pos`). Linked into sender + app. |
| `src/receiver.cpp` | SSDP broadcast, SDL2 fullscreen render (aspect-fit, never stretch), per-connection display-size refresh + zero-dimension probe fast path, hosts the sidecar services (8082/8083/8084). VSync stays enabled; when later stream bytes are already pending, a bounded catch-up skips stale texture upload/present work but still decodes every coded AU in order to preserve reference frames. Extend sessions raise their window once when it opens (Windows: briefly toggle `HWND_TOPMOST` → `HWND_NOTOPMOST`, since a background process's plain `HWND_TOP`/`SetForegroundWindow` can leave the window behind the foreground app; elsewhere `SDL_RaiseWindow`) so it starts in front without staying always-on-top. |
| `src/kvm_core.cpp/.h` | portable stitch plumbing: sockets/time, controller auth, heartbeat receive. |
| `src/kvm_target.cpp/.h` | shared 8084 target: listener, receive policy, lease, feature/token negotiation, heartbeat loop; platform seam = `KvmTargetOps`. |
| `src/kvm_x11.cpp` | Linux/X11 target: XTest (`dlopen`), Xlib metrics, scan code → evdev → X key code, held-input release. |
| `src/kvm_x11_ctl.cpp` | Linux/X11 controller: XInput2 raw motion; `XGrabKeyboard` + regular KeyPress events (raw keys are grab-suppressed) and passive `XGrabButton` 1..9 (active pointer grabs suppress raw motion); XFixes cursor hiding; XTest local-release at entry; owns the 3 px XDND strip and passes `g_remote_x/y` to 8085 drops. `MIVARA_KVM_TRACE=1` traces input. |
| `src/kvm_stub.cpp` | macOS/other stubs. |
| `src/kvm.cpp/.h` | Windows stitch backend: controller = low-level hooks + Raw Input edge detection + SPSC ring → socket; target ops = `接收策略` enforcement + `SendInput` injection + GDI drag ghost + 8085 reverse-drop watcher. `kvmRunControllerResilient` reconnects a lost session (1–30 s backoff, `state=reconnecting`) and preserves the side; every re-entry clears the stale EventQueue, window class and reverse listener. Protocol v2 reuses the 8081 auth frames (`KvmTargetAuth`/`KvmClientAuth`); manual mode calls the same approval path. Side is controller-only state, switchable mid-session; `kvmSideKey`/`kvmSideFromKey` are inline in the header. Windows controller/target backend; the header is shared with app (`KVM_PORT`/`kvmSupported`). Reverse drag: `KVM_FEATURE_REVERSE_DROP` + `KVM_EV_RDRAG`; the controller keeps the target button held while carrying back and runs an 8087 listener/gate (see protocol.md). Windows back-crossing still needs the ~24 px `KVM_BACK_DRAG_HYSTERESIS`. Drag-ghost icon: `KVM_FEATURE_DRAG_ICON` (bit 8) is advertised in `KvmHello` and echoed in `KvmReply`; `KVM_EV_DRAG_ICON_INFO`/`DATA` carry a ≤48×48 BGRA shell image (thumbnail, else icon, extracted with `IShellItemImageFactory` off the hook/message loop and bounded at 800 ms controller-side / 250 ms reverse-side) so the peer's card shows the item's real icon; the drain thread sends a queued burst in one batch, and the reverse watcher retries the name/icon after `FILES_END`; an old peer never sets the bit and never sees the frames. `KVM_FEATURE_DRAG_IMAGE` (0x10) additionally carries the source Explorer's exact `DragImageBits` (helper pipe `IMG_BEGIN/CHUNK/END`, ≤36,864 premultiplied BGRA pixels, `KVM_EV_DRAG_IMAGE_INFO/DATA`), which the peer blits at cursor-offset and prefers over the reconstructed card |
| `src/drop.cpp/.h` | opt-in stitch file-drop channel on TCP 8085: per-session token gate from 8084, `DropHello`/manifest/chunk protocol, SHA-256 verification, path sanitisation and limits (1000 items / 2 GiB). Copy-only; never moves or deletes the source. Windows target uses `%LOCALAPPDATA%\Mivara\Drop` + OLE. Linux target stages under `$XDG_CACHE_HOME/mivara/drop`, offers the items via XDND to a known file-manager window at `hello.x/y` (other apps ignored; (0,0) means no remote cursor), else copies to `$XDG_DOWNLOAD_DIR/Mivara` / `~/Downloads/Mivara` (`MIVARA_DROP_DIR`) with `fallback=1`. Reverse works on both sides: the controller runs a second `dropServiceRun` on 8087 with the session token, handles RDRAG/name/icon/image, keeps the target button held and resolves the destination from its own cursor; a Linux target's `sessionBegin` runs a 3 px XDND strip on the facing edge and sends `dropSendFiles(DROP_FLAG_REVERSE)` on drop. `src/kvm_ghost_x11.*` draws the shared card/real image (ARGB with a compositor, opaque otherwise). `dropSendFiles` takes a true=continue `g_drop_run` flag (never inverted). Reverse resolves from the controller cursor (`GetCursorPos` / `XQueryPointer`), not `hello.x/y`. |
| `src/filexfer.cpp/.h` | independent two-way file channel on TCP 8086 (protocol **v2**, both ends must match), linked into app + receiver. Separate `file_transfer_accept` opt-in (default off), same open/password/manual policy with auth purpose 3 and shared failure throttle, but its own single-client slot (no 8081/8084 lease). App worker browses local/remote directories and queues LIST/PUT/GET/MKDIR; after admission the service sends one INFO frame with its device name, read by the client before READY on BOTH handshake paths. LIST entries carry `flags(u8: dir, hidden) + name + size(u64) + mtime(u64)`; hidden is a UI filter only. MKDIR creates one component relative to a pinned parent (Windows adds `FILE_ADD_SUBDIRECTORY` to the final handle). Length-prefixed UTF-8 paths with platform-independent `validWireName` and separate `validLocalName` filtering (a locally invalid name is a recoverable `FT_ERR_PATH`, not a protocol failure); bounded frames, 64 KiB chunks, SHA-256; directory handles are pinned and child opens/temp creation/commit are handle-relative; same-directory temporary files and no-overwrite commit, with a residual same-directory temp-name race if the directory is concurrently writable; collision stems are truncated to the target component limit. Cancelling an upload sends ABORT and reuses the connection; cancelling a download is terminal because the sender never reads mid-stream. The app client accepts numeric IP literals only (`AI_NUMERICHOST`) and has one pending operation; multi-select is a GUI-side queue. Cross-platform; no SDL in the core. |
| `src/dropshell.cpp/.h` | Windows Shell half: after a successful commit, `dropPlaceIcons()` re-finds the Explorer/desktop view for the destination (`SWC_DESKTOP` for the Desktop folder, otherwise the window whose current folder matches), and positions each copied icon at the release point via `IFolderView::SelectAndPositionItems`; it skips silently when `GetAutoArrange()` is on or the view is hidden, and never affects the copy result. Resolves the folder under the release point (Explorer active view via `IShellWindows`/`IFolderView`, or the desktop), validates it (local fixed drive, no reparse point, blocked startup/system locations), commits staged top-level items with `SHFileOperationW` + unique names, and launches/reads the Medium-integrity `stitchcap.exe` helper over a **pair of one-way named pipes**. Do not collapse them into one duplex handle: a named-pipe handle without `FILE_FLAG_OVERLAPPED` is a synchronous file object, and Windows serialises every operation on it, so the reader's always-pending `ReadFile` blocks any `WriteFile` from another thread in both directions (the helper could never report DRAG/FILES; SIDE/QUIT would hang). Both server ends are opened `FILE_FLAG_OVERLAPPED` and the reader waits in 50 ms slices + `CancelIoEx` on stop, so a helper that dies before connecting can never wedge `dropHelperStart`/`dropHelperStop`. The pipes carry an explicit Medium mandatory label + a DACL for the interactive user: the sender is High (requireAdministrator) and a default pipe would inherit a High label, which MIC no-write-up then denies to the Medium helper. The Explorer view is obtained with `IShellView::QueryInterface(IID_IFolderView)` and its window with the inherited `IShellView::GetWindow`; Windows 11 26200 returns `E_NOINTERFACE` for `GetItemObject(SVGIO_BACKGROUND, IID_IFolderView)` and for a QI to `IOleWindow`, so the classic route silently falls back to Downloads\Mivara. |
| `src/stitchcap.cpp` | tiny asInvoker helper (separate `bin/stitchcap.exe`, no admin manifest): a 3-pixel topmost OLE drop target on the shared edge, captures `CF_HDROP` on `DragEnter`, forwards paths over the one-way **tx** pipe and reads `SIDE`/`QUIT` from the one-way **rx** pipe (never one duplex handle — see `dropshell.cpp`; the pending read would block every write), advertises `DROPEFFECT_COPY` from `DragEnter`/`DragOver` and returns `DROPEFFECT_NONE` from `Drop`, so it never copies locally. The COPY verdict is required: with a NONE effect OLE never calls `Drop` on release and invokes `DragLeave` instead, which would erase the capture exactly when the controller needs it. Must run at Medium integrity (launched with the shell token) or UIPI blocks Explorer's drop. Its `DragEnter` notification is asynchronous, so the controller does **not** consume the captured list only once at the edge crossing: when the list is not there yet, the held left button stays un-armed on the target for a 200 ms grace window (`g_btn_arm_pending`, resolved from `WM_INPUT`/`WM_TIMER` by `pollPendingDrag`) and the crossing becomes a file drag as soon as the paths arrive. A NODRAG (Esc/DragLeave) clears the atomic `dropHelperDragLive()` flag, so a cancelled drag is never turned into a copy at release. The helper's OLE `Drop` deliberately sends **no** NODRAG: the controller posts its drop work before Explorer processes the release and calls `Drop`, so the captured paths must stay readable until that message runs. Every physical left-button down discards any earlier capture (including a press made while controlling the peer, where no local drag can be running), and `KVM_WM_DROP` re-reads `dropHelperDragLive()` before starting a transfer — the `mouseProc` check is only an observation, and a late DragLeave/NODRAG (Esc) must still cancel. A capture is adopted only for a button whose press reached this desktop (`g_btn_local[1]`); a press swallowed in Remote must never replay a stale selection. A release inside the grace window is **never decided inside it** — the `DragEnter` notification is itself in flight, so absence of a capture proves nothing. `KVM_WM_DROP` and `pollPendingDrag` wait out the 200 ms window, then keep waiting while the helper has announced a drag but not finished the list (`dropHelperDragPending`, a slow CF_HDROP render such as a cloud file) up to a 2 s hard cap. A capture that arrives then starts the transfer at the release point snapshotted in `g_drop_rel_x/y`; a captured drag that was cancelled is left alone; only a gesture with no drag announcement at all is completed as an ordinary click, and only after the window. A non-HDROP `DragEnter` sends `NODRAG` immediately so it never waits out the cap. All of this is controller-local; no wire message is added. |
| `src/auth.cpp/.h` | shared authorization primitives: SHA-256 / HMAC-SHA256 / PBKDF2-HMAC-SHA256 (FIPS 180-4 / RFC 2104 / RFC 8018, with self-test vectors), CSPRNG, constant-time compare, password rule (4–8 printable ASCII, not all spaces, ASCII letters case-folded to lower case before PBKDF2), config record validation, the purpose-separated HMAC proof (`MIVARA_AUTH_PURPOSE_VIDEO` / `_STITCH`), the 32-byte session-token gate with conditional clear, the process-wide cross-port session lease (`mivaraSessionClaim/Promote/Release/Owner`), and one shared per-source failure throttle used by 8081 and 8084. No per-response synchronous TCP probe. Parses `NAME:` into `DiscoveredDevice.name` |

| `src/codec.h/.cpp` | FFmpeg Encoder/Decoder (H.264/H.265/AV1). Linked into sender + receiver only (app is FFmpeg-free). Encoder: hardware first; software libx264/libx265 use slice threading with `min(4, max(2, cores/2))` threads — keep `FF_THREAD_SLICE`, frame threading adds delay. Decoder: **software frame+slice threading by default** (`min(4, max(1, cores/2))`; one extra frame of latency, but a single thread cannot carry a 1440p live stream). Windows D3D11VA is opt-in via `MIVARA_DECODE=hw`: it uses avcodec's own frames context (a hand-built NV12 pool returns `E_INVALIDARG` on some drivers) and downloads each frame with `av_hwframe_transfer_data` — measured 11.7 ms/frame at 1440p versus 5.3 ms for the four-thread software path on the project laptop, so it is not the default. 4:4:4 never asks for D3D11VA (`CODEC_FLAG_CHROMA_444`); AV1 stays on dav1d. A hardware decoder that opens but silently emits nothing for eight AUs (observed: 4:4:4 opened as `h264_d3d11va`, zero frames, no error) is rebuilt in software and the stream resyncs on the next IDR — `Decoder::implName()` reports the live choice (`h264_d3d11va` / `hevc (sw, 4 threads)`) and the receiver logs it after the handshake and after every `CTRL_RECONFIG`. |
| `src/config.h/.cpp` | GUI settings (%LOCALAPPDATA%\\Mivara\\config.ini), key=value (incl. `auto_start` → Task Scheduler `Mivara` job; `applyAutoStart` returns the state read back from `schtasks /query`, never the requested one, and startup `reconcileAutoStart` re-registers a missing/disabled task or drops a leftover one; `auto_receive` (default 0; the only persisted startup preference), `theme` = light\|dark\|system, `extend_res` = auto\|WxH, `vdd_mode_write` = always\|never (default always; legacy `ask` is read as always), `stitch_side` = left\|right\|top\|bottom, `file_transfer_accept` = 0\|1 (8086 remote browse/read/write, default 0), `auth_mode` = open\|password\|manual (unknown ⇒ manual), `auth_salt`/`auth_hash` (hex PBKDF2 record; the password itself is never written), `auth_iter`, `tray_hint_shown`) |

It offers 显示主界面, live status rows, 历史连接, and 退出; live status rows are hover submenus too (显示主界面 + 停止投屏/扩展/拼接 or 停止接收), and each host opens a **submenu on hover** whose first line is the last mode/time/use count and whose actions are 投屏/扩展/拼接/文件传输, so a host can be replayed without restoring the window. | `src/app.cpp` | SDL2 + SDL2_ttf GUI launcher: header (logo + wordmark + version; on Windows the main window is created `SDL_WINDOW_BORDERLESS` — toggling the caption off after creation leaves a stale DWM frame that can flash the old title bar — `WS_EX_APPWINDOW` keeps the taskbar entry, the DWM corner preference rounds it, and the same strip carries the custom minimize/close buttons, with `mainWindowHitTest` turning the rest of it into the drag area; plus 更新 button, present only while a release is waiting + icon appearance switcher: sun 亮色 / moon 暗色 / monitor 跟随系统) over a left nav (主页/设置) + session flows and connection history inside 主页 (the name-following folder icon opens SCR_FILES, a two-pane local/remote browser driven by the `ftClient*` worker/event queue; it has multi-select checkboxes, a serial transfer queue in `FileTask`/`g_file_tasks` with pause/resume/cancel/clear, new-folder (local `ftLocalMkdir`, remote MKDIR), editable path boxes, a hidden-items display filter, local/remote device names, and a per-frame `filePump()` that starts the next queued item only when the client is idle. `FileLayout`/`fileLayout(fileCanvas(detached))` is shared by `buildFileButtons()` and `drawFilePage()`; the page may instead live in its own SDL window (`g_file_win`/`g_file_ren`/`g_file_buttons`/`g_file_hot`/`g_file_press`, `file_transfer_detach` config), with mouse/wheel/text/key routed by `windowID` and file-window input gated while a main-window modal is open. Mirror/extend show the live `statLine1`/`statLine2` stats directly; stitch adds the `BTN_STITCH_SWITCH_*` chips (`STITCH|side=…`) and a control hint. `resolveHomeScreen()`/`launchStream()` keep every sender session on `SCR_HOME` (`launchStream` treats a different target/mode as a direct switch: `stopSender()` then a fresh launch; the same target+mode is a no-op), and `homeSenderFailed()` keeps the card with 日志/重试/关闭; spawns sender/receiver as child processes with hidden console + stdout pipe (STAT| home session card + log window) and a **stdin pipe carrying `SETP|` / `STITCH|` / `AUTH|` / `RX|` / `STOP|mivara` lines**; STAT lines are queued by the reader thread and applied by `drainChildStats()` on the GUI thread (SDL/`SDL_StartTextInput` must never run on the reader); the sender's password modal and the receiver's approval prompt are both app-side dialogs answered over stdin. Layout lives in the `shared layout` macro block — `buildButtons()` (hit rects) and `renderScreen()` (painted rects) both read it, so a control can never be drawn in one place and clicked in another; keep it that way. Appearance now has a single control (the header switcher), but its ids are still matched against the `kThemeIds` table, never derived by subtracting a base: the old derived form assumed two ranges (header + 外观 card) and its `(id >= BTN_SET_THEME_BASE) ? …` test was true for the header ids too (8020 ≥ 7070), indexing `modes[950]` out of bounds and silently making every header click fall back to 亮色. **Display scale (`g_uiScale`)** — the layout is a fixed 880×700 logical grid and SDL makes the process per-monitor DPI aware, so without this the UI is drawn 1:1 and lands 25 % small on a 125 % display with one-pixel CJK strokes (the "jagged text" complaint). main() resolves it once (quarter steps, capped to the usable screen), the window is created at `uiPx(WIN_*)`, `SDL_RenderSetScale` scales every shape, fonts open at `uiPx(size)` and text blits itself in device pixels (`drawTextPx`), pointer coords are divided by `uiCoord()` at the event boundary (`floor`, not `lround` — the renderer paints a scaled rect as `[floor(x*s), ceil((x+w)*s))`, so rounding to nearest shifts every hit rect a pixel left at 2× and makes an edge-sharing chip select its neighbour), and `fitText()` compares in device pixels. Any new layout constant stays logical; any new direct pixel measurement must go through `uiPx`/`uiCoord` or it will be wrong at ≠1×. **Shape antialiasing** — SDL's shape primitives have no AA, and `SDL_RenderSetScale` scales a primitive's *coordinates* but not its *thickness*, so at 1.25× the shipped build drew the toggle pills, the warning triangle and every 1px hairline as striped scanline bands on the D3D9 backend. `fillCircle` / `fillRoundRect` / `drawRing` / `drawGlyph` / `glyphWarning` therefore blit a cached coverage mask (`g_masks`, per-renderer, dropped in `closeLogWindow` and at exit) instead of calling the primitives. Invariants: masks are baked by running the **shipped rasteriser** (`fillCircleRaw` / `fillRoundRectRaw`, kept verbatim as `*Raw`) at `MASK_SS`× by multiplying the *geometry*, never by setting the render scale — the software backend scales a `RenderDrawLine`'s coordinates but not its thickness, so a scaled scanline combs the shape; a glyph body's stroke width is hardcoded in canvas pixels, so **glyph masks bake at logical resolution** and are upscaled with `SDL_ScaleModeLinear` (baking them supersampled shrinks every stem to a hairline); AA passes run inside a `ScaleScope` (save → force 1.0 → restore) because `SDL_RenderCopyEx` honours the ambient scale; `fillRoundRect`'s corner-mask blits must abut the edge bands exactly, never overlap; every mask's transparent pixels must carry **white** RGB — `MaskCanvas` clears to `(0,0,0,0)`, so a mask must be built through `coverageFrom` (which forces `0x00FFFFFF`) rather than uploaded raw, because the linear upscale interpolates RGB as well as alpha and a black transparent pixel multiplies the glyph by its own coverage a second time, greying every antialiased edge; and each shape must be baked about the **centre of the output pixel's supersample block** (`R * MASK_SS + MASK_SS / 2`), not the block's first canvas pixel, or the whole shape lands a fraction of a device pixel up-left (the disc's coverage centroid sits 0.13 device px from the pre-AA rasteriser's placement after this correction, 0.38 before). Note the placement convention the masks must preserve: a disc at logical `(cx, cy)` is centred on **pixel index** `uiPx(cx)`, i.e. continuous `uiPx(cx) + 0.5` — matching the pre-AA `fillCircleRaw` — which is a constant 0.5 px off jagprobe's analytic "ideal centre", so that probe's absolute disc RMS is biased and must not be read as a placement error. Any new shape drawn with a raw SDL primitive will be jagged at ≠1× — route it through a mask. Extend launches no longer prompt: the sender may append the receiver's mode to `vdd_settings.xml` by default, and `vdd_mode_write=never` in config.ini is the opt-out (there is no in-GUI control; the prompt was removed deliberately, so do not re-add a MessageBox here). The 画质与编码 card header carries a `?` button (`BTN_SET_QUALITY_HELP`) that opens `docs/help/quality.html` in the default browser; the page ships with `docs/` (installer and both Linux packages copy it wholesale). Locate it relative to the executable: dev/Windows/portable `<root>/bin/app[.exe]` → `<root>/docs/help/quality.html`, Linux `install.sh` → `<prefix>/share/doc/mivara/docs/help/quality.html`, `.deb` → `/usr/share/doc/mivara/docs/help/quality.html`; `MIVARA_HELP_PAGE` overrides. The GUI runs elevated, so Windows hands the file to the full-path `explorer.exe` (never the browser directly) exactly like `updateOpenReleasePage`. |
| `src/update.h/.cpp` | app-only update check + in-app updater (settings 更新 row, home banner, header button, nav dot). Check = one HTTPS GET of `releases/latest`, version from the 302 `Location` — **never `api.github.com`** (60/h per unauthenticated IP). - `sender` CLI: `sender [ip] [port] [--mode mirror|extend|stitch] [--stitch-side left|right|top|bottom] [--codec auto|h264|h265|av1|raw|rle] [--hw 0|1] [--bitrate <kbps>] [--quality 0-51] [--fps <n>] [--scale <pct>] [--chroma 420|444] [--extend-res auto|WxH] [--vdd-add-modes 0|1]`. `--mode` skips all interactive prompts — the GUI depends on it (an unknown value is an error, never a fall-through to the prompt). Keep it working non-interactively. `--stitch-side` is where the peer sits (default `right`); an unknown value is a hard error. `--mode stitch` is resolved before discovery so the direct-connect probe uses TCP 8084, and it returns after `kvmRunControllerResilient()` — no capture, VDD, codec or 8081/8082/8083 traffic; lost sessions reconnect in the background and the stdin reader stays live — but it **does** start the stdin reader first, because the GUI switches sides with `STITCH|side=…` lines (the streaming path starts its own reader later; do not start it twice). Extend mode with `--extend-res auto` (the default) probes the receiver's current display size before creating the VDD; `--vdd-add-modes 1` permits appending a missing exact mode to the driver's `vdd_settings.xml` (the GUI enables it by default; `vdd_mode_write=never` opts out, and the CLI stays opt-in). After streaming starts, a reader thread consumes stdin lines (`SETP|k=v|…` / `PING` / `STOP|mivara`, the owner-stop line) — stdin may be a GUI pipe, so never treat it as an interactive prompt channel once the loop begins.
- File-size orientation: `app.cpp` (~5600 lines) is by far the largest source, then `receiver.cpp` (~2300), `sender.cpp` (~2150), `kvm.cpp` (~2140) and `ports.cpp` (~1825). `auth.cpp` (~570) and `tray.cpp` (~580) stay small on purpose.
- `receiver`'s 8082/8083 sidecar services are cooperatively stoppable: both take a stop callback (`gpu_stop_fn` / `ports_stop_fn`, receiver passes `mivara_service_should_stop` which reads the single `g_running` flag), gate `accept` behind a 1 s `select()`, and use stop-aware `recv`/`send` wrappers so an idle persistent client cannot pin the join. Each complete request read/write also has an absolute 30 s deadline enforced inside the wait itself (not just by an outer loop that an idle select would never reach); client connect has a 5 s bound. POSIX 8083 accepts at most 4 worker threads. Accepted sockets are switched to non-blocking after `accept` — a select-for-write only promises *some* space, so a blocking `send()` of a multi-MB response could otherwise ignore the stop flag for the whole TCP retransmission timeout; `EAGAIN`/`EWOULDBLOCK` loops back through the 1 s wait. `ports_service_run` also tracks its POSIX worker threads and waits up to 2 s for them before returning (logging if any remain). The only work that can delay shutdown beyond ~1–2 s is an in-flight `collect_ports()` (Windows table walk / macOS `lsof`) or a single compute op — the stop flag is checked on the next I/O wait. This makes `main`'s joins complete, so the final stats flush, socket close and shutdown summary are reachable. **Stopping a child (`stopChild`) is pipe-first:** when the child has a stdin pipe (the default launch; the receiver always does), the app writes the shared `STOP|mivara` line and waits, and both stdin readers treat it as a normal shutdown. That is the primary path because a GUI parent **cannot deliver Ctrl+C to a child console** on current Windows — verified on 11 26200: `GenerateConsoleCtrlEvent(CTRL_C_EVENT, 0)` returns success but no handler ever runs, so the old Ctrl+C-only sequence always sat out the full 8 s and hard-killed (the receiver had the same 8 s problem without a console to attach to). The line is longer than the 8-character password rule so it is honoured even while a password prompt is pending. Without a pipe (visible status console, `show_status_console=1`) the fallback is `AttachConsole` + `CTRL_BREAK_EVENT` behind a guard handler, with `FreeConsole` **before** the wait — otherwise the console teardown when the child exits terminates the attached GUI. Hard kill after 8 s, then `vddForceDetach` for extend. The sender also closes the video socket before `vddShutdown()`, so the receiver leaves the session at once instead of holding the last frame through the multi-second VDD teardown (POSIX GUI: SIGINT → 3 s → SIGKILL). With `show_status_console=1`, an in-session SDL quit/ESC and POSIX SIGINT now reach full cleanup; `gpuStatsWriterThread` sleeps in 1 s chunks so it cannot overrun the 8 s wait.
- The 8082 compute service and the 8083 port inspector require the **32-byte session token** issued by an authorized 8081 handshake (`gpu_service_set_token_check` / `ports_service_set_token_check`, both wired to `rxTokenCheck`). The token is read on connect and **re-checked before every request** (before 8083's `collect_ports` and before the kill operation), so a connection opened during a session loses access on its next request once the session ends; a new connection presenting the old token is refused. The gate is cleared with `mivaraSessionTokenClearIf()` so an ending session cannot wipe a newer one.
- The 8085 file-drop listener (`dropServiceRun`) runs beside the 8084 listener and is joined on every receiver exit path. It serves only a connection carrying the 32-byte token installed by an authorized 8084 session; an empty/expired gate answers `DROP_ERR_AUTH`. It is a companion of the stitch session: no cross-mode slot, no second approval. On Windows the target resolves the release point (Explorer/desktop) on an STA worker with PerMonitorV2 DPI awareness, stages privately, verifies every file, then uses the shell copy engine; on Linux/X11 `drop.cpp` stages under `$XDG_CACHE_HOME/mivara/drop` and uses a temporary XDND source (see the drop row). The same service runs on the controller's 8087 reverse port; a Linux target's facing-edge XDND strip is started by `sessionBegin`. Both the sender (`--file-drop`) and receiver (`--accept-files` / `file_drop_accept`) default to off. `stitchcap.exe` is launched before the 8084 hello with the shell token; if it cannot run at Medium, the capability bit is not set and the session continues without file drop.
- The 8086 file-transfer listener (`ftServiceRun`) starts beside 8085/8084 and is joined on every receiver exit path. It admits only when `file_transfer_accept=1`, performs its own purpose-3 authorization and shares the password throttle, but does **not** claim the video/stitch session lease. The separate enabled flag is checked before every request, so `RX|reload` revokes an existing file connection on its next operation. A second file client gets an explicit BUSY. Protocol v2 sends one INFO frame with the service device name after admission; LIST entries add hidden/mtime and MKDIR creates one folder relative to the pinned parent. The app-side client owns peer-network and file-content work on one worker; SDL consumes bounded structured events on the GUI thread and runs a GUI-side queue for multi-select (one pending op in the core). The client rejects hostnames and uses `AI_NUMERICHOST`/`AI_NUMERICSERV` before starting that worker, so a stalled DNS resolver cannot block `ftClientStop`'s join. Local home resolution and directory enumeration are currently synchronous on the GUI thread, not on that worker. The page can be embedded in the main window or detached into its own SDL window; the main window's nav does not end a detached session, and file-window input is gated while a main-window modal is open.
- The 8084 stitch listener (`kvmServiceRun`, shared in `kvm_target.cpp`; the Windows hook/injection backend is selected through `KvmTargetOps`) follows the same cooperative pattern but **polls the `running` flag, not a stop flag**: `kvmRunController`/`kvmServiceRun` take `std::atomic<bool>` where **true = keep running** (both callers pass `g_running`). Getting this inverted makes the listener exit at start-up while 8081/8082/8083 keep working — the symptom is a missing 8084 in `netstat` plus `[kvm] stitch listener stopped` right after `… on TCP 8084`. Every exit path joins the thread from `main`. One controller at a time: the session runs on its **own thread** so the listener stays responsive — while it is active, a second controller is accepted and answered `KVM_ERR_BUSY` immediately instead of sitting in the accept backlog for the whole session. Read its hello before replying: closing with unread data makes Windows send an RST that discards the BUSY reply. Both ends enable TCP keepalive (15 s idle, 3 s interval): a silent idle peer that loses power never sends a FIN, so without it the session thread would wedge the only slot forever. Every send goes through `kvmSendAll`, which **never retries a blocking send after a timeout**: Winsock may have queued an unreported prefix, and re-sending would duplicate bytes in the fixed stream. The stall tolerance comes from a **2 s `SO_SNDTIMEO`** on both ends (the old 300 ms let a brief 8085/Wi-Fi stall tear down the session). `EventQueue::pushMove` also refuses to fill the last 512 slots, so a move flood during a slow send can never evict a key-up/button-up and leave the peer holding Ctrl or the left button. A handshake budget bounds hello (3 s), identity (10 s) and proof (125 s, 140 s total), and a source with an unfinished handshake or an abandon cooldown is refused `KVM_ERR_BUSY`; the budget is what keeps an unauthenticated peer from pinning the port. Before any event is accepted, 8084 enforces the **same 接收策略 as 8081** (protocol v2): open grants immediately; password requires the PBKDF2/HMAC proof with purpose 2 and the shared per-source failure throttle; manual calls the receiver's `waitManualApproval`/`nativeManualPrompt` — that approval is the *only* prompt, never a second, friendlier dialog. 8081 and 8084 share one process-wide session slot (`auth.cpp`): the owner is pre-checked before the challenge, the slot is claimed before a manual prompt or right before the grant, and the other port answers BUSY while it is held. Approval prompts are serialized across both ports; a second device gets `KVM_APPROVAL_BUSY` → `HS_ERR_BUSY` instead of replacing the visible prompt. A version-1 peer is refused `KVM_ERR_VERSION`; a missing/corrupt password record is refused `HS_ERR_AUTH_CONFIG`, never downgraded. `kvmServiceRun(running, &auth)` takes the hooks; `nullptr` falls back to the native prompt but still treats the request as manual (fail closed). An **explicit** refusal suppresses further prompts **from that source IP** for 60 s (keyed on the address, so one hostile host cannot auto-deny every other controller on the LAN); an unanswered 30 s prompt arms no cooldown. The native-prompt watcher also `select`s the session socket and dismisses the box as soon as the controller disconnects, so the slot is not held until the timeout; a peer that hangs up during the prompt gets a 3 s backoff (per source in a bounded 8-entry table **and** in one global tick, so rotating addresses only bypasses the per-source half; a non-blocking FIN check skips the dialog entirely and the wait polls the socket so a vanished peer frees the slot at once), and two dialogs are never shown less than 1.5 s apart. Only a real `IDNO` counts as a refusal: `MessageBoxW` returning 0 (no interactive window station, out of resources) must not arm the 60 s cooldown — it is logged as a prompt failure and answered without one. Held-input bookkeeping stores the exact scan code and extended flag that were injected and releases those on the way out — never a VK→scan reconstruction, which does not round-trip for numpad Enter, media keys or a differing layout. Heartbeats run every 3 s with a 9 s deadline (`KVM_HEARTBEAT_INTERVAL_MS`/`_TIMEOUT_MS`); a lost controller session is retried by the resilient wrapper and both ends log a stable `[kvm]` reason token. Screen metrics are agreed at handshake; a mid-session resolution change is picked up by the reconnect handshake. The native fallback prompt is a topmost `MessageBoxW` (default No, 30 s auto-dismiss, force-closed by a watcher thread on shutdown) — never move it to the accept thread's critical path without keeping that force-close, or receiver shutdown hangs on a modal dialog. **Posting `WM_CLOSE` / `WM_SYSCOMMAND(SC_CLOSE)` to a MessageBox does not close it** (verified on Windows 11 26200: the box stays up forever, so an auto-dismiss built on it silently never fires and shutdown hangs); the watcher enumerates the owner thread's `#32770` windows with `EnumThreadWindows` and posts `WM_COMMAND(IDNO)` instead. Authorization here is **admission control, not encryption**: neither the injected events nor the video stream are encrypted.
