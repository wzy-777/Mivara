# Architecture maintainer guide

Authoritative guidance for source wiring, command-line behavior, service lifecycles and app/updater invariants. Read the relevant sections before changing those areas.

## Architecture (actual wiring)

| File | Role |
|------|------|
| `src/sender.cpp` | capture (GDI/X11/CoreGraphics), handshake, streaming, runtime reconfigure (SETP). Extend mode probes the receiver's display size (zero-dimension HsRequestV2) before sizing the VDD. |
| `src/vdd.cpp/.h` | Windows virtual display (MttVDD) lifecycle: enable/disable PnP device (SetupAPI), independently sourced CCD attach/detach/position with non-MTT layout preservation and read-back verification, mode enumeration/closest-aspect fallback, and opt-in exact-mode append to `vdd_settings.xml`. Linked into sender + app. |
| `src/receiver.cpp` | SSDP broadcast, SDL2 fullscreen render (aspect-fit, never stretch), per-connection display-size refresh + zero-dimension probe fast path, hosts the sidecar services (8082/8083/8084) |
| `src/kvm.cpp/.h` | 拼接 (stitch) software KVM on TCP 8084: controller = low-level hooks + Raw Input edge detection + SPSC ring → socket; target = `接收策略` enforcement + `SendInput` injection. Protocol v2 reuses the 8081 authorization frames (`HsAuthStart`/`HsRequestExtV3`/`HsAuthProof`/`HsResponseV2`) through `KvmTargetAuth`/`KvmClientAuth` hooks; manual mode calls the **same** approval path as 8081. The peer may sit on any of the four sides (controller-only state, switchable mid-session; `kvmSideKey`/`kvmSideFromKey` are **inline in the header** because `app` includes it but never links kvm.cpp). Windows only; sender/receiver/app share the header (app only needs `KVM_PORT`/`kvmSupported`), never the video/VDD path |
| `src/auth.cpp/.h` | shared authorization primitives: SHA-256 / HMAC-SHA256 / PBKDF2-HMAC-SHA256 (FIPS 180-4 / RFC 2104 / RFC 8018, with self-test vectors), CSPRNG, constant-time compare, password rule (4–8 printable ASCII, not all spaces, ASCII letters case-folded to lower case before PBKDF2), config record validation, the purpose-separated HMAC proof (`MIVARA_AUTH_PURPOSE_VIDEO` / `_STITCH`), the 32-byte session-token gate with conditional clear, the process-wide cross-port session lease (`mivaraSessionClaim/Promote/Release/Owner`), and one shared per-source failure throttle used by 8081 and 8084. Lives here because `kvm.o` is linked into both sender and receiver and must not reference receiver symbols. Linked into sender + receiver + app |
| `src/discover.cpp/.h` | SSDP discovery (UDP 1900): non-blocking concurrent NIC listeners, one total deadline, three retransmits 100 ms apart, per-interface directed broadcast and early source-IP/port dedupe. `DiscoveryOptions` supplies a cancellation token + `onDevice` callback; the GUI applies generation-tagged updates on its main thread so the first device appears immediately and stale/cancelled scans cannot switch screens. No per-response synchronous TCP probe. Parses `NAME:` into `DiscoveredDevice.name` |
| `src/gpu_accelerate.c/.h` | remote CPU offload protocol (RLE compress / color convert) served on 8082 — only used by the RLE codec path |
| `src/ports.cpp/.h` | remote port inspector on 8083 (LIST/GET/KILL) |
| `src/proto.h` | protocol v3 shared by sender/receiver: HsRequestV2/HsResponseV2, HsAuthStart/HsRequestExtV3/HsAuthProof/HsResponseExtV3, CodecId, HsStatus, control packets |
| `src/codec.h/.cpp` | FFmpeg Encoder/Decoder (H.264/H.265/AV1). Linked into sender + receiver only (app is FFmpeg-free) |
| `src/config.h/.cpp` | GUI settings (%LOCALAPPDATA%\\Mivara\\config.ini), key=value (incl. `auto_start` → Task Scheduler `Mivara` job, `auto_receive` (default 0; the only persisted startup preference), `theme` = light\|dark\|system, `extend_res` = auto\|WxH, `vdd_mode_write` = always\|never (default always; legacy `ask` is read as always), `stitch_side` = left\|right\|top\|bottom, `auth_mode` = open\|password\|manual (unknown ⇒ manual), `auth_salt`/`auth_hash` (hex PBKDF2 record; the password itself is never written), `auth_iter`, `tray_hint_shown`) |
| `src/history.h/.cpp` | connection history (history.ini, cap 20, newest first) |
| `src/theme.h/.cpp` | GUI palette: light/dark token sets + follow-system resolution (`themeTick`, Windows registry `AppsUseLightTheme` polled every 2 s; macOS/Linux sampled once per process — the popen is never repeated, so at most one UI-thread sample is ever taken, which lands on the first 跟随系统 click if the app was launched in light/dark). app.cpp colours come from `theme()`; the only exceptions are the two mode-independent constants in theme.h (`DANGER_SOLID`, `SWITCH_ON`), plain white (toggle knob, the danger-button label, the chip/banner hover washes) and plain black (the danger button's hover wash). |
| `src/tray.h/.cpp` | Windows notification-area icon + single instance. Close hides the window (session keeps running), icon click / 显示主界面 restores, right-click offers 显示主界面/退出, tooltip mirrors the receive/session state, balloons announce a pending approval while hidden, the first hide shows a one-time hint (`tray_hint_shown`). A `Local\\` named mutex makes a second launch wake the running instance. Hiding and quitting never change 接收开关 / 自动接收. No-op on POSIX (`trayInit` returns false) |
| `src/app.cpp` | SDL2 + SDL2_ttf GUI launcher: header (wordmark + 更新 button, present only while a release is waiting + icon appearance switcher: sun 亮色 / moon 暗色 / monitor 跟随系统) over a left nav (主页/设置) + session flows and connection history inside 主页 (主页 starts with 连接设备; the receiver is a low-weight status bar with six states — 接收已关闭/正在开启/等待连接/等待授权/正在接收/开启失败 — each with its own action); SSDP search, device list (投屏/扩展/拼接), manual IP, settings split into 常规 / 接收与安全 tabs (the latter carries 允许其他设备连接到此电脑, 启动软件时自动开启接收, the three 授权方式 and the single-field password editor — one masked field, no "密码" caption and no confirm row; 显示密码 is the only typo safeguard); 拼接 opens a modal four-way direction chooser (`g_stitch_ask` + `BTN_STITCH_SIDE_*`, drawn as an overlay and enforced as a modal in both `buildButtons` and `onButton`), and a running stitch session shows the same four choices as `BTN_STITCH_SWITCH_*` chips in the status panel (sent as `STITCH|side=…`); spawns sender/receiver as child processes with hidden console + stdout pipe (STAT| status panel + log window) and a **stdin pipe carrying `SETP|` / `STITCH|` / `AUTH|` / `RX|` / `STOP|mivara` lines**; STAT lines are queued by the reader thread and applied by `drainChildStats()` on the GUI thread (SDL/`SDL_StartTextInput` must never run on the reader); the sender's password modal and the receiver's approval prompt are both app-side dialogs answered over stdin. Layout lives in the `shared layout` macro block — `buildButtons()` (hit rects) and `renderScreen()` (painted rects) both read it, so a control can never be drawn in one place and clicked in another; keep it that way. Appearance is the only setting with two controls (header + 外观 card), so its ids are matched against the `kThemeIds` table, never derived by subtracting a base: a `(id >= BTN_SET_THEME_BASE) ? …` range test is true for the header ids too (8020 ≥ 7070) and once indexed `modes[950]` out of bounds, which silently made every header click fall back to 亮色. **Display scale (`g_uiScale`)** — the layout is a fixed 880×700 logical grid and SDL makes the process per-monitor DPI aware, so without this the UI is drawn 1:1 and lands 25 % small on a 125 % display with one-pixel CJK strokes (the "jagged text" complaint). main() resolves it once (quarter steps, capped to the usable screen), the window is created at `uiPx(WIN_*)`, `SDL_RenderSetScale` scales every shape, fonts open at `uiPx(size)` and text blits itself in device pixels (`drawTextPx`), pointer coords are divided by `uiCoord()` at the event boundary (`floor`, not `lround` — the renderer paints a scaled rect as `[floor(x*s), ceil((x+w)*s))`, so rounding to nearest shifts every hit rect a pixel left at 2× and makes an edge-sharing chip select its neighbour), and `fitText()` compares in device pixels. Any new layout constant stays logical; any new direct pixel measurement must go through `uiPx`/`uiCoord` or it will be wrong at ≠1×. **Shape antialiasing** — SDL's shape primitives have no AA, and `SDL_RenderSetScale` scales a primitive's *coordinates* but not its *thickness*, so at 1.25× the shipped build drew the toggle pills, the warning triangle and every 1px hairline as striped scanline bands on the D3D9 backend. `fillCircle` / `fillRoundRect` / `drawRing` / `drawGlyph` / `glyphWarning` therefore blit a cached coverage mask (`g_masks`, per-renderer, dropped in `closeLogWindow` and at exit) instead of calling the primitives. Invariants: masks are baked by running the **shipped rasteriser** (`fillCircleRaw` / `fillRoundRectRaw`, kept verbatim as `*Raw`) at `MASK_SS`× by multiplying the *geometry*, never by setting the render scale — the software backend scales a `RenderDrawLine`'s coordinates but not its thickness, so a scaled scanline combs the shape; a glyph body's stroke width is hardcoded in canvas pixels, so **glyph masks bake at logical resolution** and are upscaled with `SDL_ScaleModeLinear` (baking them supersampled shrinks every stem to a hairline); AA passes run inside a `ScaleScope` (save → force 1.0 → restore) because `SDL_RenderCopyEx` honours the ambient scale; `fillRoundRect`'s corner-mask blits must abut the edge bands exactly, never overlap; every mask's transparent pixels must carry **white** RGB — `MaskCanvas` clears to `(0,0,0,0)`, so a mask must be built through `coverageFrom` (which forces `0x00FFFFFF`) rather than uploaded raw, because the linear upscale interpolates RGB as well as alpha and a black transparent pixel multiplies the glyph by its own coverage a second time, greying every antialiased edge; and each shape must be baked about the **centre of the output pixel's supersample block** (`R * MASK_SS + MASK_SS / 2`), not the block's first canvas pixel, or the whole shape lands a fraction of a device pixel up-left (the disc's coverage centroid sits 0.13 device px from the pre-AA rasteriser's placement after this correction, 0.38 before). Note the placement convention the masks must preserve: a disc at logical `(cx, cy)` is centred on **pixel index** `uiPx(cx)`, i.e. continuous `uiPx(cx) + 0.5` — matching the pre-AA `fillCircleRaw` — which is a constant 0.5 px off jagprobe's analytic "ideal centre", so that probe's absolute disc RMS is biased and must not be read as a placement error. Any new shape drawn with a raw SDL primitive will be jagged at ≠1× — route it through a mask. Extend launches no longer prompt: the sender may append the receiver's mode to `vdd_settings.xml` by default, and `vdd_mode_write=never` in config.ini is the opt-out (there is no in-GUI control; the prompt was removed deliberately, so do not re-add a MessageBox here). |
| `src/update.h/.cpp` | app-only update check + in-app updater (settings 更新 row, home banner, header button, nav dot). Check = one HTTPS GET of `releases/latest`, version from the 302 `Location` — **never `api.github.com`** (60/h per unauthenticated IP). Windows download lands in `%ProgramData%\Mivara\Updates`, which is taken over with owner=Administrators + a **protected** DACL (SYSTEM/Admins full, Users read/execute, inheritance dropped) and then read back to confirm; the installer is verified against the release's `SHA256SUMS.txt` (fail-closed). Download rejects reparse points, deletes any old target and uses `CREATE_NEW`, then secures/verifies the file's own owner + DACL; launch rechecks path security and hashes through a handle that denies write/delete sharing until `ShellExecuteW` returns. POSIX builds only check + open the release page. Links `-lwinhttp -lbcrypt -ladvapi32`. **One-click path:** the header button (`BTN_HDR_UPDATE`, ghost hit area painted by `drawHeader`) sets `g_upd_auto_install`, and the `updateTake()` completion hook runs `startInstall()` itself once the package verifies — except while a sender/receiver child is live, where quitting would kill the session; then the button turns green and waits for a second click. Only the header button arms that flag: 下载更新 in the 更新 card still stops at 立即安装. |
| `src/version.h` | single version source (`MIVARA_VERSION`, bare `X.Y.Z`) consumed by C++ **and by the Inno preprocessor** — keep it comment-free. |

- `ports.cpp` has a hidden `main()` behind `-DPORTS_MAIN` — can be compiled standalone as a port-inspection CLI. The makefile never sets this flag; don't be confused by two `main` functions in the tree.
- `sender` CLI: `sender [ip] [port] [--mode mirror|extend|stitch] [--stitch-side left|right|top|bottom] [--codec auto|h264|h265|av1|raw|rle] [--hw 0|1] [--bitrate <kbps>] [--quality 0-51] [--fps <n>] [--scale <pct>] [--chroma 420|444] [--extend-res auto|WxH] [--vdd-add-modes 0|1]`. `--mode` skips all interactive prompts — the GUI depends on it (an unknown value is an error, never a fall-through to the prompt). Keep it working non-interactively. `--stitch-side` is where the peer sits (default `right`); an unknown value is a hard error. `--mode stitch` is resolved before discovery so the direct-connect probe uses TCP 8084, and it returns after `kvmRunController()` — no capture, VDD, codec or 8081/8082/8083 traffic — but it **does** start the stdin reader first, because the GUI switches sides with `STITCH|side=…` lines (the streaming path starts its own reader later; do not start it twice). The controller also passes `KvmClientAuth` hooks: a password policy asks on the same stdin channel (`AUTH|password=…` from the GUI, a bare line in a console) and reports progress as `STAT|event=auth|state=need_password|authenticating|waiting|granted|cancelled`; a manual policy waits for the receiver's approval. Extend mode with `--extend-res auto` (the default) probes the receiver's current display size before creating the VDD; `--vdd-add-modes 1` permits appending a missing exact mode to the driver's `vdd_settings.xml` (the GUI enables it by default; `vdd_mode_write=never` opts out, and the CLI stays opt-in). After streaming starts, a reader thread consumes stdin lines (`SETP|k=v|…` / `PING` / `STOP|mivara`, the owner-stop line) — stdin may be a GUI pipe, so never treat it as an interactive prompt channel once the loop begins.
- File-size orientation: `app.cpp` (~5600 lines) is by far the largest source, then `receiver.cpp` (~2300), `sender.cpp` (~2150), `kvm.cpp` (~2140) and `ports.cpp` (~1825). `auth.cpp` (~570) and `tray.cpp` (~310) stay small on purpose.
- `receiver`'s 8082/8083 sidecar services are cooperatively stoppable: both take a stop callback (`gpu_stop_fn` / `ports_stop_fn`, receiver passes `mivara_service_should_stop` which reads the single `g_running` flag), gate `accept` behind a 1 s `select()`, and use stop-aware `recv`/`send` wrappers so an idle persistent client cannot pin the join. Each complete request read/write also has an absolute 30 s deadline enforced inside the wait itself (not just by an outer loop that an idle select would never reach); client connect has a 5 s bound. POSIX 8083 accepts at most 4 worker threads. Accepted sockets are switched to non-blocking after `accept` — a select-for-write only promises *some* space, so a blocking `send()` of a multi-MB response could otherwise ignore the stop flag for the whole TCP retransmission timeout; `EAGAIN`/`EWOULDBLOCK` loops back through the 1 s wait. `ports_service_run` also tracks its POSIX worker threads and waits up to 2 s for them before returning (logging if any remain). The only work that can delay shutdown beyond ~1–2 s is an in-flight `collect_ports()` (Windows table walk / macOS `lsof`) or a single compute op — the stop flag is checked on the next I/O wait. This makes `main`'s joins complete, so the final stats flush, socket close and shutdown summary are reachable. **Stopping a child (`stopChild`) is pipe-first:** when the child has a stdin pipe (the default launch; the receiver always does), the app writes the shared `STOP|mivara` line and waits, and both stdin readers treat it as a normal shutdown. That is the primary path because a GUI parent **cannot deliver Ctrl+C to a child console** on current Windows — verified on 11 26200: `GenerateConsoleCtrlEvent(CTRL_C_EVENT, 0)` returns success but no handler ever runs, so the old Ctrl+C-only sequence always sat out the full 8 s and hard-killed (the receiver had the same 8 s problem without a console to attach to). The line is longer than the 8-character password rule so it is honoured even while a password prompt is pending. Without a pipe (visible status console, `show_status_console=1`) the fallback is `AttachConsole` + `CTRL_BREAK_EVENT` behind a guard handler, with `FreeConsole` **before** the wait — otherwise the console teardown when the child exits terminates the attached GUI. Hard kill after 8 s, then `vddForceDetach` for extend. The sender also closes the video socket before `vddShutdown()`, so the receiver leaves the session at once instead of holding the last frame through the multi-second VDD teardown (POSIX GUI: SIGINT → 3 s → SIGKILL). With `show_status_console=1`, an in-session SDL quit/ESC and POSIX SIGINT now reach full cleanup; `gpuStatsWriterThread` sleeps in 1 s chunks so it cannot overrun the 8 s wait.
- The 8082 compute service and the 8083 port inspector require the **32-byte session token** issued by an authorized 8081 handshake (`gpu_service_set_token_check` / `ports_service_set_token_check`, both wired to `rxTokenCheck`). The token is read on connect and **re-checked before every request** (before 8083's `collect_ports` and before the kill operation), so a connection opened during a session loses access on its next request once the session ends; a new connection presenting the old token is refused. The gate is cleared with `mivaraSessionTokenClearIf()` so an ending session cannot wipe a newer one.
- The 8084 stitch listener (`kvmServiceRun`) follows the same cooperative pattern but **polls the `running` flag, not a stop flag**: `kvmRunController`/`kvmServiceRun` take `std::atomic<bool>` where **true = keep running** (both callers pass `g_running`). Getting this inverted makes the listener exit at start-up while 8081/8082/8083 keep working — the symptom is a missing 8084 in `netstat` plus `[kvm] stitch listener stopped` right after `… on TCP 8084`. Every exit path joins the thread from `main`. One controller at a time: the session runs on its **own thread** so the listener stays responsive — while it is active, a second controller is accepted and answered `KVM_ERR_BUSY` immediately instead of sitting in the accept backlog for the whole session. Read its hello before replying: closing a socket with unread received data makes Windows send an RST, which discards the BUSY reply and surfaces as `WSAECONNRESET` on the controller. Both ends enable TCP keepalive (15 s idle, 3 s interval): a KVM is silent whenever the user is idle, so a controller that loses power or Wi-Fi never sends a FIN, and without keepalive the session thread would wedge the only slot forever (with the peer's keys possibly still held down). A handshake budget bounds hello (3 s), identity (10 s) and proof (125 s, 140 s total), and a source with an unfinished handshake or an abandon cooldown is refused `KVM_ERR_BUSY`; the budget is what keeps an unauthenticated peer from pinning the port. Before any event is accepted, 8084 enforces the **same 接收策略 as 8081** (protocol v2): open grants immediately; password requires the PBKDF2/HMAC proof with purpose 2 and the shared per-source failure throttle; manual calls the receiver's `waitManualApproval`/`nativeManualPrompt` — that approval is the *only* prompt, never a second, friendlier dialog. 8081 and 8084 share one process-wide session slot (`auth.cpp`): the owner is pre-checked before the challenge, the slot is claimed before a manual prompt or right before the grant, and the other port answers BUSY while it is held. Approval prompts are serialized across both ports; a second device gets `KVM_APPROVAL_BUSY` → `HS_ERR_BUSY` instead of replacing the visible prompt. A version-1 peer is refused `KVM_ERR_VERSION`; a missing/corrupt password record is refused `HS_ERR_AUTH_CONFIG`, never downgraded. `kvmServiceRun(running, &auth)` takes the hooks; `nullptr` falls back to the native prompt but still treats the request as manual (fail closed). An **explicit** refusal suppresses further prompts **from that source IP** for 60 s (keyed on the address, so one hostile host cannot auto-deny every other controller on the LAN); an unanswered 30 s prompt arms no cooldown. The native-prompt watcher also `select`s the session socket and dismisses the box as soon as the controller disconnects — otherwise the sole slot stays busy until the timeout and the reconnect is answered BUSY; a peer that hangs up during the prompt gets a 3 s backoff (per source in a bounded 8-entry table **and** in one global tick, so rotating addresses only bypasses the per-source half; a non-blocking FIN check skips the dialog entirely and the wait polls the socket so a vanished peer frees the slot at once), and two dialogs are never shown less than 1.5 s apart. Only a real `IDNO` counts as a refusal: `MessageBoxW` returning 0 (no interactive window station, out of resources) must not arm the 60 s cooldown — it is logged as a prompt failure and answered without one. Held-input bookkeeping stores the exact scan code and extended flag that were injected and releases those on the way out — never a VK→scan reconstruction, which does not round-trip for numpad Enter, media keys or a differing layout. Screen metrics are agreed at handshake; a mid-session resolution change on the target is not renegotiated (reconnect). The native fallback prompt is a topmost `MessageBoxW` (default No, 30 s auto-dismiss, force-closed by a watcher thread on shutdown) — never move it to the accept thread's critical path without keeping that force-close, or receiver shutdown hangs on a modal dialog. **Posting `WM_CLOSE` / `WM_SYSCOMMAND(SC_CLOSE)` to a MessageBox does not close it** (verified on Windows 11 26200: the box stays up forever, so an auto-dismiss built on it silently never fires and shutdown hangs); the watcher enumerates the owner thread's `#32770` windows with `EnumThreadWindows` and posts `WM_COMMAND(IDNO)` instead. Authorization here is **admission control, not encryption**: neither the injected events nor the video stream are encrypted.
- The updater is self-contained and must stay that way: it never touches the protocol, the VDD path, the children or the config, and the worker thread never calls SDL/`logPush`/`configSave` (the UI polls `updateTake()` once per frame). Invariants to preserve: only `github.com/wzy-777/Mivara` is contacted (User-Agent only, nothing uploaded); redirects are followed only for downloads and the **final URL must land on `github.com`/`*.githubusercontent.com` over HTTPS or no body byte is read**; the tag is validated to a fixed charset before it builds a URL or file name; in-app install is fail-closed on a missing `SHA256SUMS.txt` entry. `src/update.cpp` carries a hidden CLI behind `-DUPDATE_TEST_MAIN` (cf. `-DPORTS_MAIN`): `unit` / `check` / `download <tag>` / `hash <file>` — the makefile never sets the flag.
