# Windows maintainer guide

Authoritative guidance for Windows-only behavior, deployment, virtual displays and stitch input. Read this file before changing those areas.

[Back to AGENTS.md](../../AGENTS.md)

## Windows specifics (easy to get wrong)

- `sender` links as a **console** subsystem app (logs + interactive prompts + Ctrl+C). `receiver` and `app` link with `-mwindows` (GUI, stdout discarded).
- `res/admin.manifest` declares **PerMonitorV2 DPI awareness** for both sender and app. The sender must be DPI-aware: in a DPI-unaware process Windows virtualises `GetSystemMetrics`/`GetMonitorInfo`/GDI capture coordinates (a 3840x2160 VDD is reported as 2560x1440 at 150 %), which silently turns the receiver-matched extend path into an upscaled stream. Don't remove it — the GUI's `g_uiScale` assumes per-monitor awareness too.
- **Original B application icon** — `res/mivara-mark.svg` is the editable transparent/black mark; `res/mivara-app.svg` is the `#2F6FEC`-background, white-mark application source. Preserve the original B exactly: `viewBox="0 0 256 256"`, two rounded outline rectangles and the `front-cutout` mask geometry (including the 16-unit stroke); never substitute another logo or redraw/thicken it. Only the **background tile** is rounded, and its `rx="54"` is not a free parameter: the white frame's outer edge sits at 24..232 with `rx=30`, so a concentric tile needs `rx = 24 + 30 = 54`. That keeps the edge and corner gutters equal at 24 units (measured: `rx` 48/52/56/60 all skew the corner gutter by 45–54 %). The four corners outside the arc are transparent, which is why the PNG/ICO rasters carry real alpha; the mark itself stays white-on-blue inside the tile, so it never depends on the desktop background. `res/mivara-{16,32,48,256}.png` are rendered from the app SVG, and `res/mivara.ico` contains 16/32/48 as 32-bit BMP entries plus 256 as PNG. `res/admin.rc` embeds the ICO as RT_ICON resource ID 1 alongside the manifest; `src/tray.cpp` loads that ID through `GetModuleHandleW(nullptr)` and falls back to `IDI_APPLICATION`. Keep `res/mivara.ico` in the `RES_ADMIN` dependencies. `src/logo_icon.h` embeds the actual 32 PNG's RGBA bytes and creates a 32x32, pitch-128 `SDL_PIXELFORMAT_RGBA32` surface with `SDL_CreateRGBSurfaceWithFormatFrom`; its pixel array must remain static because the surface references external storage rather than owning a copy.
- **Stitch (software KVM) input plumbing** — `kvm.cpp` is Windows-only (`kvmSupported()` is inline in `kvm.h` so `app` needs no link). Controller: `WH_MOUSE_LL`/`WH_KEYBOARD_LL` + a hidden top-level window with `RIDEV_INPUTSINK` Raw Input; **never do socket I/O inside a hook** (overrunning `LowLevelHooksTimeout` silently unhooks it) — events go through an SPSC ring to a drain thread, which posts a disconnect back to the message loop. Edge crossing must use `WM_INPUT` relative deltas: once the cursor is clamped at the virtual-desktop edge the hook's `pt` stops changing. Nothing but the ring push may run inside a hook callback: `ShowCursor`/`SetCursorPos`/`std::cout` (panic hotkey, mode changes) are deferred to the message loop with `PostMessage`; the button *state* table is updated in both Local and Remote (a press or release that straddles a mode switch would otherwise be replayed as a phantom drag or never re-armed), and both hooks pass `*_INJECTED` input through untouched instead of forwarding it. Target: the configured 接收策略 first (protocol v2 — open, password proof, or the receiver's manual-approval prompt; when the receiver runs without the app hooks a topmost `MessageBoxW`, default No, 30 s auto-dismiss + shutdown watcher is the fallback), then `SendInput` (absolute + `MOUSEEVENTF_VIRTUALDESK`, scan-code keys). The 8084 authorization exchange is **on the session thread before any event is read** — never start injecting before it completes, and never add an 8084-only path that skips it. Both roles poll the caller's `g_running` as **true = running**. `-luser32` is in `SENDER_LIBS`/`RECEIVER_LIBS` for exactly this file. Elevation: a standalone `bin/receiver.exe` is not elevated, so injection stops at its integrity level (UIPI — no input into elevated windows, no secure-desktop input); launched from `app.exe` it inherits the GUI's `requireAdministrator` token and can reach elevated windows, which is why the receive policy matters. This is a behavior difference worth stating in the user docs, not a bug to "fix" by de-elevating a child Windows cannot easily de-elevate.
- **Stitch file drop (8085) is copy-only and opt-in.** The controller side is `src/drop.cpp` + `src/dropshell.cpp`; the target side resolves the folder under the release point and copies the staged items there. The controller cannot receive an ongoing Explorer `DoDragDrop` in its High-integrity process (UIPI blocks Medium Explorer from dropping onto a High window), so `bin/stitchcap.exe` is a separate **asInvoker** helper launched with the shell token (`CreateProcessWithTokenW`). It owns a **3-pixel topmost strip** on the shared edge, captures `CF_HDROP` in `DragEnter`, forwards the paths over a named pipe and returns `DROPEFFECT_NONE`; it never copies anything locally. The strip is deliberately 3 px so normal edge use is almost unaffected, but it is still a 3 px dead zone. The helper reports its integrity level; the controller accepts it only when it is no higher than the shell token it duplicated (Medium normally, High when Explorer itself is elevated). If the helper cannot reach that level, the controller does not advertise the feature. The target resolves Explorer via `IShellWindows` → `IServiceProvider` → `IShellBrowser` → `QueryActiveShellView` → `IFolderView` (MinGW's `IFolderView` has no `ItemAt`, so the item cell is hit-tested with `GetItemPosition` + `GetSpacing`), and the desktop via `Progman`/`WorkerW` → `FOLDERID_Desktop`. The destination must be a local fixed drive, not a reparse point, and not a startup/system location; the staging directory is `%LOCALAPPDATA%\Mivara\Drop\<transfer>-<tick>-<seq>` (residue is swept when the 8085 listener starts), each file is verified with SHA-256, and the commit uses `SHFileOperationW` with `FOF_SILENT|FOF_NOCONFIRMATION|FOF_NOERRORUI|FOF_NOCONFIRMMKDIR|FOF_RENAMEONCOLLISION` and a unique name (never overwrite; the rename flag only covers a race during the copy). The default fallback destination is `%USERPROFILE%\Downloads\Mivara`; if Downloads is not on a local fixed drive or cannot be created, it becomes `%LOCALAPPDATA%\Mivara\Received`. The destination directory is reopened without delete sharing and pinned for the copy, which blocks a junction swap of the folder itself after validation; a swapped parent component remains a residual TOCTOU because `SHFileOperationW` cannot write relative to a handle. Shutdown is checked between top-level items, but `SHFileOperationW` itself is not interruptible. Per-top-level-item commit is not atomic: a partial commit is reported as an error with `items`/`failed` counts and may leave the failed item's partial data; never delete a destination by guessing. Never add a delete/move step: the source is opened read-only and is never modified. The release point is the target's screen coordinate sent over 8085; the 8084 event stream is untouched.
- SDL2_ttf needs a CJK font at runtime; `app.cpp` walks an ~11-path candidate list (`msyh.ttc`/`simhei.ttf`/NotoSansCJK/wqy/…) and exits with an error if none is found. Caveat: the list also contains non-CJK `DejaVuSans.ttf`, so on a machine with no CJK font the probe can "succeed" via DejaVu and render tofu instead of erroring.
- The runtime DLL closure must sit in `bin/` next to the exes. `make copy-dlls` resolves it with `objdump` over the import tables, **not `ldd`**: MSYS2's `ldd` debug-loads the target, and `CreateProcess` on the `requireAdministrator` `sender`/`app` fails with `ERROR_ELEVATION_REQUIRED`, so `ldd` silently reports nothing for exactly those two binaries and `SDL2_ttf.dll` / the newer FFmpeg closure never got copied. After adding a library, run `make copy-dlls` and verify the import closure with `objdump -p` (system DLLs and `api-ms-win-*` excluded).
- Extend mode needs the MttVDD indirect-display driver installed once (`vdd/install_vdd.ps1`). **Inno Setup is a 32-bit process**, so a bare `{sys}\WindowsPowerShell\...\powershell.exe` starts 32-bit PowerShell, where `%SystemRoot%\System32` is redirected to SysWOW64 and `pnputil.exe` "does not exist" (the installer then reports the VDD install failed). The .iss starts `{sysnative}\WindowsPowerShell\...` and the script self-boots through `Sysnative` when `[Environment]::Is64BitProcess` is false, so both the installer and a manual run from a 32-bit shell reach the real 64-bit pnputil. Do not remove either guard. Windows PowerShell 5.1's `Get-PnpDevice` has no `-HardwareId` parameter; `Get-MivaraVddDevice` must filter the `HardwareID` property through the pipeline so device detection works from the installer on a stock machine. The bundled DevCon has no `create` command; create the root-enumerated device with `devcon install <full INF path> Root\MttVDD` (no `@` prefix), and keep the existing-device guard because every `install` call creates a new devnode. The virtual display lifecycle lives in `src/vdd.cpp`/`vdd.h` (`vddStartup`/`vddShutdown`/`vddForceDetach`, CCD API + SetupAPI device enable/disable) and is linked into both `sender` and `app`. The VDD mode list is read by the driver **once at start-up** from `vdd_settings.xml` (registry `SettingsPath`/`VDDPATH` override first, else `%SystemRoot%\System32\drivers\UMDF\vdd_settings.xml`); a size absent from that list cannot be applied. `vddEnsureMode()` can append the receiver's exact size (numeric-only and even, bounded 320x240..7680x4320, session mutex, pristine `.mivara.bak`, unique temp + `ReplaceFile` which keeps the System32 ACL, in-memory rollback, re-read verification) but refuses to touch the file while any VDD CCD path is ACTIVE — that would yank a display a live session owns; `vddStartup(..., reloadFirst=true)` then does one disable/enable cycle (never while a path is active) so the UMDF stack re-reads the file; otherwise `vddStartup` enumerates the exposed modes and uses the closest aspect. The startup snapshot preserves the active non-MTT paths, sources, clone groups and modes; enabling the device may automatically clone physical targets, so detach only those MTT paths and restore the snapshot before attaching. Identify the MTT target by its `DISPLAY#MTT1337#` path, enumerate `QDC_ALL_PATHS`, and select a target-available path whose source is not occupied, preferring the MTT adapter's own source. Allocate a distinct clone group: a second target on a physical source or in the same clone group is mirroring, not Extend. Never apply a global `SDC_TOPOLOGY_EXTEND` or preserve the pre-enable MTT clone in the baseline. Resolve the GDI name from the accepted active CCD source and verify desktop attachment; check every GDI monitor index for MTT rather than assuming `Monitor0`. After sizing/positioning, read back both MTT independence and the non-MTT layout. Use `SDC_USE_SUPPLIED_DISPLAY_CONFIG | SDC_ALLOW_CHANGES | SDC_VIRTUAL_MODE_AWARE` without `SDC_SAVE_TO_DATABASE` so session changes are not persisted. Normal cleanup preserves the current non-MTT layout; a failed startup restores the saved pre-start baseline. The receiver aspect-fits the stream (black bars) instead of stretching, so a residual mismatch is never distortion. **Never break the Ctrl+C graceful path** — a hard exit leaves the virtual display attached to the user's desktop. Covered exit paths: normal end, send failure, Ctrl+C, console-window close (detaches inside the `CTRL_CLOSE_EVENT` handler), `atexit`. The GUI stops the sender over its stdin pipe (`STOP|mivara`) — a GUI parent cannot deliver Ctrl+C to a child console on current Windows, so this is the primary path. `GenerateConsoleCtrlEvent` remains only the fallback for the visible-console launch (no stdin pipe) and must use `CTRL_BREAK_EVENT` (Ctrl+Break is delivered where Ctrl+C is not), detaching with `FreeConsole` **before** the wait because the console teardown after the child exits would otherwise terminate the attached GUI. Hard-kill only after an 8 s timeout, and call `vddForceDetach()` as a safety net after a hard kill.
- A CCD detach alone leaves the monitor visible in Settings > Display — teardown MUST also disable the PnP device (hardware ID `Root\MttVDD`, instance `ROOT\DISPLAY\000x`; match on hardware IDs, never touch other vendors' virtual display adapters). Enabling/disabling requires elevation: `sender` and `app` embed a `requireAdministrator` manifest via `res/admin.rc` + `res/admin.manifest` (windres, see makefile `RES_ADMIN`). `receiver` is not elevated. Disable failure degrades gracefully (warn + CCD-only). A disabled device has no CCD path — `vddStartup` must enable the device **before** the `vddInstalled()` gate.
- **Tray + single instance** live in `src/tray.cpp` (Windows only, `-lshell32 -luser32` in `APP_LIBS`). The icon is owned by a dedicated thread with a message-only window (`HWND_MESSAGE`); tray callbacks only set atomics, and the SDL loop drains them once per frame (`trayTakeRequests`), so no tray callback ever touches SDL. Closing the main window hides it (`SDL_HideWindow`) while the receiver/sender children keep running; the log window is hidden and restored too. Consequences worth preserving: `SDL_QUIT` means "hide" only when the tray exists — otherwise it must still quit; `requestQuit()` is the single exit path (it sets `g_exit_requested` and posts `SDL_QUIT`, letting the loop save settings and clean children); an exit while a session is active asks for confirmation (`MessageBoxW`, `MB_DEFBUTTON2`, default = keep running); the first hide shows a one-time balloon and persists `tray_hint_shown`; hiding/quitting **must not** write `auto_receive` (and `allow_receive` is never persisted at all — the receive switch is runtime state). Single instance is the `Local\\Mivara.App.SingleInstance` mutex claimed **before** the SDL window is created. Waking the existing instance must not depend on the icon: the primary also creates the named event `Local\\Mivara.App.Show` and a small wait thread, and a second launch sets that event **and** still tries `FindWindowExW(HWND_MESSAGE, …)` + `kMsgShow` as a fallback, then exits. If `Shell_NotifyIconW(NIM_ADD)` fails, the message-only window and its loop stay alive as that fallback (`trayInit` returns false meaning "no icon", not "no IPC"), so the GUI must drain `trayTakeRequests()` unconditionally rather than gating it on `g_tray_ok`. `trayShutdown()` stops the wake thread, posts `WM_CLOSE` and joins — call it on **every** exit path after the children are stopped but before the SDL teardown (including the SDL_CreateWindow/Renderer failure path), and release the mutex last via `traySingleInstanceRelease()`.
- **Auto-start stays a Task Scheduler `onlogon` job with `/rl highest`** (`applyAutoStart` in `app.cpp`; task name `Mivara`, also removed by the installer's `[UninstallRun]`). `app.exe` and `sender.exe` embed `requireAdministrator`, so an `HKCU\...\Run` entry would re-trigger UAC at every logon; the scheduled task starts the app elevated and silently. The app registers/removes the task on 保存设置, reads the result back with `schtasks /query`, folds the real state into `config.ini`, and repairs a missing/leftover task at startup (`reconcileAutoStart`). `schtasks /delete` exits non-zero when the task is absent — never report that as a registration failure (check existence first).
- `scripts/*.bat` are convenience wrappers that launch `bin/` exes; `启动投屏发送.bat` takes the receiver IP as an argument.
