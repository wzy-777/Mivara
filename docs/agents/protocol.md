# Protocol maintainer guide

Authoritative guidance for wire protocols, runtime control channels, discovery and network behavior. Read this file before changing those areas.

[Back to AGENTS.md](../../AGENTS.md)

## Protocol constants (defined in `src/proto.h`)

- Handshake over TCP 8081 (**protocol v2**, all u32 network byte order, magic `0x54564853` 'TVHS'):
  - Request (sender→receiver) `HsRequestV2` **48 bytes**: magic, version=2, width, height, fps, mode, codec, codec_flags, bitrate_kbps, quality, gop_frames, reserved.
  - Response (receiver→sender) `HsResponseV2` **36 bytes**: magic, version, recv_width, recv_height, status, codec, codec_flags, reserved[2].
  - `mode`: 0 = mirror, 1 = extend. `codec`: 0=raw 1=rle 2=h264 3=h265 4=av1. `status`: 0=ok 1=version 2=codec 3=dims 4=decoder 5=legacy.
  - Receiver peeks 4 bytes first: non-TVHS magic ⇒ legacy peer, explicit error (no black screen). Old 16-byte handshake is rejected.
  - **Display-size probe (no version bump):** a normal `HsRequestV2` with `width=0 && height=0` asks only for `HsResponseV2.recv_width/recv_height`; the receiver answers with `status=HS_ERR_DIMS` and returns before creating a window or a decoder (it does one SDL_Init/SDL_Quit to query the display mode, so the reply is in physical pixels). No window appears and no client stats are recorded. Probe replies require `version == 2`. Extend mode uses it to size the VDD before the real handshake.
- Stream packets: `[u32 pkt_size][payload]`; control = `u32 0xFFFFFFFF` + `u32 ctrl_type` + body. `CTRL_RESIZE=1` body = HsRequestV2; `CTRL_FORCE_IDR=2` / `CTRL_EOS=3` body empty; `CTRL_RECONFIG=4` body = HsRequestV2 (runtime param change — receiver re-opens the decoder and sets `skip_until_key`, see the shared resize/reconfig handler in receiver.cpp).
- Coded payload = one access unit per packet (annex-B / OBU). Raw/RLE unchanged. 8082 remote RLE is connected **only** while `codec=rle` (connect/disconnect follows runtime codec switches).
- STAT| machine-readable status lines on stdout (parsed by the GUI): `STAT|k=v|k=v|...` with keys t/frames/fps/kbps/codec/hw/mode/src/dst/quality or `event=start|stop|error|applied|pong|stitch` + `msg=` (stitch adds `state=waiting|local|remote` and `side=left|right|top|bottom`; the GUI renders the state in `drawStatPanel` and the side as its four-way switch). The parser replaces its state per line, but not every line is a full snapshot: only periodic lines and `event=applied` carry the full key set — `start`/`stop`/`error`/`pong` carry subsets (sender `error` = `msg=` only; the receiver emits its own `start`/`stop`/`error`/`resize`/`reconfig` variants). The GUI special-cases event lines; check `parseStatLine` in app.cpp before changing emitter key sets.
- GUI→sender stdin line protocol (runtime reconfigure): `SETP|codec=…|hw=…|bitrate=…|quality=…|fps=…|scale=…|chroma=…` (any subset; keys map to the CLI flags; numeric values must be whole decimal numbers — parse with a strict whole-token check, never `atoi`; all-or-nothing validation, reply `STAT|event=applied|…` or `STAT|event=error|msg=bad_value_*`). `STITCH|side=left|right|top|bottom` switches a running stitch controller's edge (applied by the message loop within one 50 ms tick; hands control back first). `PING` → `STAT|event=pong`.
- Ports: 1900/udp SSDP, 8081/tcp video, 8082/tcp compute offload (`GPU_ACCEL_PORT`), 8083/tcp port inspector (`PORTS_SERVICE_PORT`), 8084/tcp stitch KVM (`KVM_PORT`, `kvm.h`).
- **Stitch channel (8084, protocol independent of v2):** `KvmHello` (16 B, magic `0x4D564B31` 'MVK1'; `reserved[0]` = the peer's side from the controller's viewpoint + 1 (1 left / 2 right / 3 top / 4 bottom), used only to word the target's consent dialog — 0/unknown means right, so a zero-filled hello from an older build is not misread as "left") → `KvmReply` (32 B: status 0 ok / 1 version / 2 denied / 3 busy + target virtual-desktop x/y/w/h) → `KvmEvent` (16 B: type 1 move / 2 button / 3 wheel / 4 key / 5 release-all / 6 ping / 7 pong). All `uint32` network byte order. `KvmHello.reserved[1]` and `KvmReply.reserved` negotiate `KVM_FEATURE_HEARTBEAT` without a version bump: new peers exchange PING/PONG every 3 s and disconnect after ~9 s without input; older peers receive no heartbeat and keep TCP keepalive. The controller drain thread also monitors EOF/errors even when no input is being sent; local stop shuts down the socket before joining, and the target releases held input on EOF. The side itself is controller-only state (the target injects absolute coordinates), so switching needs no message. `HsRequestV2.mode` stays 0/1 — stitch never touches 8081, and `handleClientConnection` normalises any other mode to mirror.
- SSDP discovery: sender probes **per local NIC** over 3 rounds (~100 ms apart), each sending multicast + 255.255.255.255 + a directed per-NIC subnet broadcast (enterprise nets often drop multicast). Replies are keyed on the **datagram source address**, with the LOCATION IP probed only as a fallback (multi-homed receivers may advertise the wrong NIC). Receiver's LOCATION uses `getLocalIPForPeer(requester)` (same-subnet NIC). Receiver advertises `NAME: <hostname>`.
- Windows `SO_RCVTIMEO`/`SO_SNDTIMEO` take DWORD milliseconds, not `struct timeval` (POSIX). Passing a timeval silently gives ~5 ms timeouts.
- Sender and receiver must be the **same binary version** (protocol v2). Mismatched builds fail the handshake with an explicit error — never silently black-screen.
